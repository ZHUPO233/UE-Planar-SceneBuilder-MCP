# 阶段一 · 资产确认

**用户要求**：根据上传图片提取所需资产**让用户确认** → 找资产，**名字对得上的就是找到了**，没找到**禁止找疑似的**，直接告知缺什么，并要求用户把【路径 + 名字】给 agent 重命名 → 最后确认资产列表并向用户确认。

**流程**：先有那张表 `config/asset_categories.json`（**11 个资产大类** + **2 个场景项**：地图大小 / 地图对应时间）→ 读图把元素**填进表里对应的大类**（有数量的填预估 `count` + `count_source`；场景项必填）→ **让用户确认这张表** → `plan_assets` 按资产名 + 文件夹名两路找 → 没资产的元素**登记白膜占位** → `confirm_assets` 逐个 `exists()` + 实测包围盒 → 交付按大类分组的清单请用户确认。

**硬规则**：① 禁止猜"疑似资产"；② 没找到不许拿别的顶替，也不许列一堆候选让用户挑；③ 缺失资产由**用户**给路径与名字；④ 用户确认前**不许摆任何东西**；⑤ 白膜只是"清单登记"，真生成在**阶段六**（官方 `PrimitiveTools` 加图元，不建资产、不存盘）；⑥ **预估值不许伪装成实测值** —— `size_source` 必须写明"预估（参考图目测，待核实）"。

⚠ 大类不是搜索参数（`find_assets` 只按资产名 / 文件夹名 / 类路径）。⚠ 两个场景项不是资产：不进资产清单，供阶段二世界范围与阶段七灯光用。

⚠ **清单里的「尺寸」是"资产自身"的包围盒，不是"场景里该有多大"**（实测：`house1` 89 cm、`tree` 16 m）。阶段二用 `scale` 换算：`footprint_m`（米）= 实测（cm）÷ 100 × `scale`（89 cm 的房子摆成 12 m 宽 → `scale` ≈ 13.5）。**偏小 / 偏大是常态 —— 用 `scale` 解决，不许为尺度换资产、更不许拿这个去问用户。**（2026-09-26 客户反馈：agent 拿「house1 实测只有 89×70×50 cm，是不是要换个房子模型」去问用户，而答案本来就在 `scale` 上。）

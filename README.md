# UEPLANE · UE 平面场景搭建（参考图驱动）

> **版本 v2.0.0**（与目录名 / 压缩包名一致）

把**一张参考图 + 一句需求**变成 UE 关卡里的场景：先规划成一份**可核对的布局**（每个物体一行：中心坐标 + 占地 + 朝向），你点头之后再在**你自己指定的关卡**里按这份布局进行整体搭建——局部微调——材质调整——环境搭建——评估迭代修改。

**它是什么**：MCP **编排层**（编排 =规划布局，调度官方工具）。链路：

```
Agent（DSH  / Cursor / Codex / ） → 本 server（stdio）→ 官方 Unreal MCP → UE
```

## 关于本MCP

AI 借助官方MCP操作UE的能力 —— 进行**可核对、可回滚、有人把关**的布局流程（详细流程见下）。所以：

-  **不是** UE 工具集的封装 —— 它**自己一步都不碰 UE**：改关卡 / 摆 Actor / 读属性，全经官方那侧。
-  **不是**"一键出成品" —— 中间有**四道必须由人点头的闸**（见下）；生成得再快，**没人看过就不许落地**。
-  **属于** 编排层 ＋ 一整套**写进代码的硬闸**：把"AI 自己觉得行"换成"**AI 干活、人看页点头**"。

一句话：**它不是自动化程度，是可控程度。**

## 最简单使用方法

**分两次复制**：**装**用第一段（**重启客户端之前**那个对话里发）；**验与用**用第二段（**重启并开新对话之后**发）。

**为什么必须分两段**：MCP 工具**只在客户端启动时读一次** —— 重启前那个对话里**还没有**这 21 个工具；重启后必须**开新对话**它们才在。所以"装"和"用"天然是两段，**合成一段只会白跑**。

### 第一段 · 重启客户端之前发（装修 + 写配置）

```
帮我装好这份 UEPLANE（UE 场景搭建 MCP 编排层）—— 这一步只需要你动手，不要调 MCP 工具。

1. 先读同目录的 SETUP.md 与 README.md，按写的做，不要凭印象。
2. 确认这份代码所在目录的路径不含空格（Trae 的配置不允许空格）；如果还没解压，先解压到一个不含空格的目录。
3. 在该目录运行 .\setup.ps1：它会建 .venv、装依赖、跑预检、写好 mcp.json / .trae/mcp.json / .cursor/mcp.json / .vscode/mcp.json，并生成 connect-config.json（给**不读工作区文件**的客户端，如 DSH）。
4. 把预检的原始输出贴给我；有报错先按报错修，别跳过、别猜。
5. 然后告诉我两件事：① 需要我做哪一次「最后动作」（重启客户端并开新对话 / 打开「启用项目级 MCP」/ 重载窗口）；② 重启后该在哪个目录开新对话。
6. 前置确认：官方那个 UE MCP 插件要开着（http://127.0.0.1:8000）—— 先确认 UE 已启动、插件已启用。

 现在还没挂上 MCP 工具，你不要去调它们；装完、把上面两件事告诉我，就停下等我重启。
```

### 第二段 · 重启并开新对话之后发（验证 + 开工）（第一段一个Agent配置完成后每次新对话可只用第二段启动）

```
我已经做完「最后动作」，这个新对话应该已经挂上 UEPLANE 的 21 个工具了。

1. 先调 official_status()：确认链路 reachable=true（工具集数量由它现算 —— 早期实测报 **52**，2026-10-12 实测为 **53**；**别把数量写死**）（这条现在也是硬闸：不先确认链路，任何碰 UE 的工具都会被拒）。
2. 再调 get_plan()（走到哪 / 闸门状态 / 页认不认数据）与 get_asset_list()（阶段一清单过没过期）—— 三个都只读，各调一次就够。
3. **开场三件调完之后，先读 `get_plan().stages`** —— 那是一份**八阶段总览**（八行：阶段 / 状态 / **依据**（哪个文件、什么值）/ **下一步该调谁**），照着它判断接手位置：哪几步已完成、现在卡在第几阶段、下一步该调哪个工具。它同时也在 `get_asset_list().stages` 里（**同一份数据**，不是各算一遍）；`official_status()` 只给一句指路（它是链路诊断，保持轻）。 它**纯离线、不碰 UE** —— 报的是现成产物（catalog/ 与 views/ 下的文件）怎么说，不是关卡的真值；要看真值得调 evaluate_layout()。
4. 把这三步的原始结果贴给我，并说明：当前卡在哪一步、下一步要我做什么（确认页 / 确认清单 / 还是等我给指令）。 要改哪几行、下一步该调谁，以 `stages` 那一行为准 —— 别凭印象讲流程。
5. 之后所有活都按 AGENTS.md 的规则走：开场先查状态、动手前过闸、**默认不存盘**（例外见 AGENTS.md：**阶段五第 ⑦ 步「用户满意 ⇒ 保存」**与**阶段六真跑成功后的自动存盘**）、不许猜资产、该停就停下等我确认。
6.  开工前先让我给参考图：**顶视图**（看平面：摆在哪 / 占地多大）+ **左右视图**（看高度与立面）。只有一张也能做，只是平面 / 高度会退化成目测预估，清单里会标「预估待核实」。
```

**唯一需要你亲自动手**的是第一段第 5 步那次「最后动作」（重启客户端并开新对话 / 打开「启用项目级 MCP」/ 重载窗口）—— 细节见 **`SETUP.md`**。

用户侧怎么用（要准备什么、在哪几次停下点头）见 **`使用说明.md`**；给 AI 的规则见 **`AGENTS.md`**（仓库里另有一份客户使用版 `使用版-AGENTS.md`；**使用包里它已改名为 `AGENTS.md`**）。

## 本MCP设置的流程阶段

> 编号与阶段名的**唯一出处**是代码 `main.py::_stage_overview()`（常量 `STAGE_NAMES_8`）；本表只说**每个阶段是做什么的**。

| 阶段 | 这一阶段是做什么的 |
|---|---|
| 一 · 资产确认（元素表 → 用户确认 → 找资产 → 使用清单） | **已实现** |
| 二 · 放置规划，出图确认（活动那份 plan + 确认页 + 验收闸门） | **已实现** |
| 三 · 资产布局生成，整体搭建（指令表 → 批量落关卡 / 增量重摆） | **已实现**（落位默认走**逐行老路**（`batch=false`，2026-10-12 改的默认值）；`batch=true`（官方 `ProgrammaticToolset.execute_tool_script` 一次调用落完整批）**从编辑器事件循环里发起时会整体失败**（`Cannot run the event loop while another loop is running`）。口径见 `docs/阶段三-资产布局生成.md`） |
| 四 · 微调（整体搭建完成之后的小改） | **已实现** |
| 五 · 材质与实例化 | **表面材质已实现**（`apply_surfaces` 贴已存在的材质 + **`create_surfaces` 把缺的从零建出来**；材质清单在 `catalog/material_list.json`（**逐条签字** —— 那是"**贴什么**"的**唯一**来源）； |
| 六 · 环境搭建（灯光 ＋ 天空/大气/天光/雾/云/后处理 ＋ 时段） | **已实现**（`setup_environment` 配整套环境、可回滚）。 **一律不存盘**的是：搭场景 / 出图 / 对账 |
| 七 · 评估与闭环迭代 | **已实现** 验收 = 你在 UE 里自己看） |
| 八 · 导出/交换（布局序列化） | **已实现，但按需 · 往后排 —— 这一版没把它编排进流程**（`export_layout` / `check_exchange` 仍在工具面里，**21 个工具**（以 `describe_toolset` 现数为准））。要跟 Blender 等 DCC 搬同一套布局时才用它；主流程走到阶段七就结束了 |

**落进 UE 的顺序固定为五层、由下往上**：① 世界地基 `ground` → ② 地皮 `grass` → ③ 建筑层 `house`
→ ④ 设施层 `road` / `sidewalk` / `path` → ⑤ 植被层 `tree` / `shrub`（代码常量 `BUILD_LAYERS` 自动排）。
其中第①层靠 plan 里一行 `ground` 白膜撑着（铺满世界、`height_m` 给厚度）—— **plan 没有这一行，
这一层就是空的**，代码不会凭空生出一块底板。

**阶段二有且只有一条检查：越界**（`planning/plan.py` 的 `bounds_check()`）。分三级：**硬 · 实体**
（`house` / `tree` / `shrub`，以及表里没有的一切 `element_key`）四角必须都在世界边界内；**软 · 铺装**
（`road` / `sidewalk` / `path` / `grass`）允许贴边、不许超出；**豁免 · 边界元素**（`ground`）它自己
就是世界边界、压线合法。**只报红、不拦**，而且**不写进 plan**（写进去会动几何指纹、把上次确认作废）。

## 硬规矩

| 闸 | 拦什么 | 落在哪 |
|---|---|---|
| **元素表** | AI 自己编元素 | `confirm_elements` 落盘后**停下等你确认** |
| **资产清单** | 拿不相干的资产顶替 | 名字**对得上才算找到**；找不到就报缺 + 请用户给【路径 + 名字】；没资产的元素登记**白膜占位** |
| **规划图** | 拿到资产表就开始搭 | 必须**有一页 + 用户点头 + 他的原话**（`user_quote`）；那一页 = `views/<活动 plan 名>_view.html`（一页 three.js，**由 `write_plan()` 在落盘时自动生成**，Agent 不许手画）；**页与数据缺一不可且必须一致**；几何一改，上次确认**自动作废** |
| **落位对账** | 摆完不知道对不对 | 落完**逐个读回核对**；对不上的行**原地报出来** |
| **先看现场**（G15 / G16） | 拿**活动那份 plan**的**纸面旧值**当现场（用户可能早就在 UE 里挪过了） | 有台账时，**改数据**（`generate_plan`）与**真落关卡**（`execute_build`）之前都必须有一份**当版**的 `evaluate_layout()` 报告（`plan_hash` 对得上盘上这一版、且真查过关卡那一维），否则**拒收** |
| **人工痕迹保护**（两步闸） | 把用户在 UE 里手拖过的东西**静默删掉** | 默认**拒收**并把清单列出来（顺带留痕"问过哪几行"）；要覆盖必须**先问、停下等用户打字、再带他本人的原话**真跑 ——  **对外只有两步**，工具侧只核对两件事：**这一批对不对得上** + **有没有他本人的原话** |
| **点名重摆**（`only_labels`，2026-10-03） | 「`plan` 与台账一致、但关卡里那几行被手拖偏了」时**没有只动那几行的路**（默认增量要动 0 行，全量重摆会把 `UEMCP/` 全删了重来） | `execute_build(only_labels=["那几行的 label"])` = **只把这几行按 plan 摆回去**；
| **微调**（阶段四） | AI 顺手改没被点名的那几行 | 走 `request_plan_change`（**记用户原话**）→ `generate_plan(patch=…)`（**只改点名的那几行**）→ `execute_build(only_labels=[…])`（**只动这几行**）； **不出图、不要二次确认**，验收 = 用户在 UE 里自己看 + agent 报数字； 复核期 `plan == 台账` ⇒ 默认增量报「要动 0 行」，**不是**「关卡没问题」——要看现场得先 `evaluate_layout()` |

贯穿全程的三条：**默认不存盘**（存不存由用户在 UE 里定 ——  **两处例外**：**阶段五第 ⑦ 步「用户满意 ⇒ 保存」**、
**阶段六真跑成功后自动存盘**，见上表那两格）· **可回滚**（环境台账 + `restore=true`）·
**增量**（改几行就只重摆那几行）。外加一条硬要求：返回数字必须**无损穿过 JSON**
（`-0.0` / `NaN` / `Infinity` 会被 Agent 整条拒收）。

**21 个工具**：`official_status`、`confirm_elements`、`find_assets`、`rename_assets`、`confirm_assets`、`get_asset_list`、`generate_plan`、`get_plan`、`request_plan_change`、`confirm_plan`、`check_build_target`、`adopt_user_edits`、`execute_build`、`export_layout`、`check_exchange`、`create_surfaces`、`apply_surfaces`、`setup_environment`、`capture_preview`、`evaluate_layout`、`reset_scene`。

 Agent**不读** MCP 的 `instructions` —— 所以要求要么写在各工具 docstring 里，要么由**代码拒收时的原文**教会调用方。都变成了代码闸（回读闸 / 规划图闸 / 用户原话 / 改动窗口 / 搭哪张图 / 人工痕迹保护 / **先看现场 G15·G16**）。同一条纪律：**参数不许被静默吞掉** —— `force_full=true` 配上别的 `mode` 现在**直接拒收**

## 限制与已知缺陷

- **必须有 UE + 官方 Unreal MCP 插件**（它固定吃 `127.0.0.1:8000`）。没开 UE 时**只有离线的那几样能用**：
  `get_plan` / 生成规划（**确认页由代码在落盘时自动生成**，这一样完全不碰 UE）**不需要 UE**；
  找资产 / 验路径（ `get_asset_list` 默认逐个 `exists()` 验活 ⇒ **它要过链路闸**）/ 落关卡 / 对账 / `capture_preview` 出图**需要**。
- **不出成品图**：它把布局落进你的关卡、贴上材质、配好环境 —— 最终效果**你在 UE 里自己看**，
  它不替你评判"像不像那张参考图"。
- **不替你点确认**：没有"一键闭环""自动确认"，**也不打算做** —— 那会绕过"看页点头"那道闸。
-  **原 D1（`find_assets` 认不出带分隔符的资产名）已于 2026-09-30 修复并实测** ——
  **改之前这两个必报 missing**（证据：`main.py` 的 `[完工-21]` 横幅）。
   **仍切不开的一种写法**：全大写紧跟小写（`MIAsphalt`）会被当成**一个词**（`_tokenize` 只认
  "小写→大写"这个边界）—— 遇到就改用其中**单个单词**当关键词（如 `Asphalt`），或先 `rename_assets` 改名。
- **重叠不检、不修**：阶段二只有一条检查（越界，分三级、**只报红不拦**）—— 这是**取舍**，不是漏做。
- - **阶段六不稳定，涉及简单材质制作尚未完全实测**
- **平台**：Windows（`setup.ps1` / PowerShell 7 更佳）+ Python 3.11+；只认 URL 的客户端用 `serve_http.py`（端口 `8770`）。

# UEPLANE · UE 平面场景搭建（参考图驱动）

> **版本 v0.8.5**（与目录名 / 压缩包名一致）

把**一张参考图 + 一句需求**变成 UE 关卡里的场景：先规划成一份**可核对的平面布局**（每个物体一行：中心坐标 + 占地 + 朝向），你点头之后再在**你自己指定的关卡**里按这份布局搭建；之后要改，**只改你指的那几处**，不推倒重来。

**它是什么**：MCP **编排层**（编排 = 它自己一步都不碰 UE，只调度官方工具）。链路：

```
Agent（DSH / Trae / Cursor / VS Code / 通用 stdio 客户端） → 本 server（stdio）→ 官方 Unreal MCP（HTTP 127.0.0.1:8000）→ UE
```

## 为什么存在（它不是什么）

AI 不缺"会调 UE 接口"的能力 —— 缺的是**可核对、可回滚、有人把关**的流程。所以：

- ❌ **不是** UE 工具集的封装 —— 它**自己一步都不碰 UE**：改关卡 / 摆 Actor / 读属性，全经官方那侧。
- ❌ **不是**"一键出成品" —— 中间有**四道必须由人点头的闸**（见下）；生成得再快，**没人看过就不许落地**。
- ✅ **是** 编排层 ＋ 一整套**写进代码的硬闸**：把"AI 自己觉得行"换成"**AI 干活、人看图点头**"。

一句话：**它卖的不是自动化程度，是可控程度。**

## 最简单使用方法

**分两次复制**：**装**用第一段（**重启客户端之前**那个对话里发）；**验与用**用第二段（**重启并开新对话之后**发）。

⚠ **为什么必须分两段**：MCP 工具**只在客户端启动时读一次** —— 重启前那个对话里**还没有**这 20 个工具；重启后必须**开新对话**它们才在。所以"装"和"用"天然是两段，**合成一段只会白跑**。

### 第一段 · 重启客户端之前发（装修 + 写配置）

```
帮我装好这份 UEPLANE（UE 场景搭建 MCP 编排层）—— 这一步只需要你动手，不要调 MCP 工具。

1. 先读同目录的 SETUP.md 与 README.md，按写的做，不要凭印象。
2. 确认这份代码所在目录的路径不含空格（Trae 的配置不允许空格）；如果还没解压，先解压到一个不含空格的目录。
3. 在该目录运行 .\setup.ps1：它会建 .venv、装依赖、跑预检、写好 mcp.json / .trae/mcp.json / .cursor/mcp.json / .vscode/mcp.json，并生成 connect-config.json（给只认 URL 的客户端）。
4. 把预检的原始输出贴给我；有报错先按报错修，别跳过、别猜。
5. 然后告诉我两件事：① 需要我做哪一次「最后动作」（重启客户端并开新对话 / 打开「启用项目级 MCP」/ 重载窗口）；② 重启后该在哪个目录开新对话。
6. 前置确认：官方那个 UE MCP 插件要开着（http://127.0.0.1:8000）—— 先确认 UE 已启动、插件已启用。

⚠ 现在还没挂上 MCP 工具，你不要去调它们；装完、把上面两件事告诉我，就停下等我重启。
```

### 第二段 · 重启并开新对话之后发（验证 + 开工）（第一段一个Agent配置完成后每次新对话可只用第二段启动）

```
我已经做完「最后动作」，这个新对话应该已经挂上 UEPLANE 的 20 个工具了。

1. 先调 official_status()：确认链路 reachable=true、官方 52 个工具集（这条现在也是硬闸：不先确认链路，任何碰 UE 的工具都会被拒）。
2. 再调 get_plan()（走到哪 / 闸门状态 / 图认不认数据）与 get_asset_list()（阶段一清单过没过期）—— 三个都只读，各调一次就够。
3. **开场三件调完之后，先读 `get_plan().stages`** —— 那是一份**八阶段总览**（八行：阶段 / 状态 / **依据**（哪个文件、什么值）/ **下一步该调谁**），照着它判断接手位置：哪几步已完成、现在卡在第几阶段、下一步该调哪个工具。⚠ 它同时也在 `get_asset_list().stages` 里（**同一份数据**，不是各算一遍）；`official_status()` 只给一句指路（它是链路诊断，保持轻）。⚠ 它**纯离线、不碰 UE** —— 报的是现成产物（catalog/ 与 views/ 下的文件）怎么说，不是关卡的真值；要看真值得调 evaluate_layout()。
4. 把这三步的原始结果贴给我，并说明：当前卡在哪一步、下一步要我做什么（确认图 / 确认清单 / 还是等我给指令）。⚠ 要改哪几行、下一步该调谁，以 `stages` 那一行为准 —— 别凭印象讲流程。
5. 之后所有活都按 AGENTS.md 的规则走：开场先查状态、动手前过闸、不存盘（唯一例外 = 阶段六，见 AGENTS.md）、不许猜资产、该停就停下等我确认。
```

⚠ **唯一需要你亲自动手**的是第一段第 5 步那次「最后动作」（重启客户端并开新对话 / 打开「启用项目级 MCP」/ 重载窗口）—— 细节见 **`SETUP.md`**。

用户侧怎么用（要准备什么、在哪几次停下点头）见 **`使用说明.md`**；给 AI 的规则见 **`AGENTS.md`**（仓库里另有一份客户使用版 `使用版-AGENTS.md`；**使用包里它已改名为 `AGENTS.md`**）。

> **阶段编号**：旧口径的「四 · 碰撞检测与布局修正」**已作废**（不再单列阶段）；本版从**七个阶段**改成
> **八个阶段** —— 插入「四 · 微调」，其后编号整体后移：材质与实例化 = **五**不变、
> 环境搭建 = **六**不变、评估与闭环迭代 = **七**不变、导出/交换 = **八**（从原来的第四阶段挪到这里）。

**落进 UE 的顺序固定为五层、由下往上**：① 世界地基 `ground` → ② 地皮 `grass` → ③ 建筑层 `house`
→ ④ 设施层 `road` / `sidewalk` / `path` → ⑤ 植被层 `tree` / `shrub`（代码常量 `BUILD_LAYERS` 自动排）。
其中第①层靠 plan 里一行 `ground` 白膜撑着（铺满世界、`height_m` 给厚度）—— **plan 没有这一行，
这一层就是空的**，代码不会凭空生出一块底板。

**阶段二有且只有一条检查：越界**（`planning/plan.py` 的 `bounds_check()`）。分三级：**硬 · 实体**
（`house` / `tree` / `shrub`，以及表里没有的一切 `element_key`）四角必须都在世界边界内；**软 · 铺装**
（`road` / `sidewalk` / `path` / `grass`）允许贴边、不许超出；**豁免 · 边界元素**（`ground`）它自己
就是世界边界、压线合法。**只报红、不拦**，而且**不写进 plan**（写进去会动几何指纹、把上次确认作废）。

被问到没做的阶段，**如实说"还没做"** —— 不许承诺。**一到七都已实现，第八（导出/交换）按需、没编排进这一版流程**；定位是"**把参考图变成可核对的布局、落进 UE、按需微调、贴上材质、配好环境、再对账**（阶段七出图 + 落位对账）"，不是"发张图就出成品效果图"——环境参数是**人在 UE 里看、再拍板**的（阶段六不出图；出图工具 `capture_preview` 归阶段七）。

## 硬规矩（都写进代码了，不靠 AI 自觉）

| 闸 | 拦什么 | 落在哪 |
|---|---|---|
| **元素表** | AI 自己编元素 | `confirm_elements` 落盘后**停下等你确认** |
| **资产清单** | 拿不相干的资产顶替 | 名字**对得上才算找到**；找不到就报缺 + 请用户给【路径 + 名字】；没资产的元素登记**白膜占位** |
| **规划图** | 拿到资产表就开始搭 | 必须**出图 + 用户点头 + 他的原话**（`user_quote`）；**数据与图缺一不可且必须一致**；几何一改，上次确认**自动作废** |
| **落位对账** | 摆完不知道对不对 | 落完**逐个读回核对**；对不上的行**原地报出来** |
| **先看现场**（G15 / G16） | 拿 `plan_v1.json` 的**纸面旧值**当现场（用户可能早就在 UE 里挪过了） | 有台账时，**改数据**（`generate_plan`）与**真落关卡**（`execute_build`）之前都必须有一份**当版**的 `evaluate_layout()` 报告（`plan_hash` 对得上盘上这一版、且真查过关卡那一维），否则**拒收** |
| **人工痕迹保护**（两步闸） | 把用户在 UE 里手拖过的东西**静默删掉** | 默认**拒收**并把清单列出来（顺带留痕"问过哪几行"）；要覆盖必须**先问、停下等用户打字、再带他本人的原话**真跑 —— ⚠ **对外只有两步**，工具侧只核对两件事：**这一批对不对得上** + **有没有他本人的原话**（⚠ 2026-10-04 撤掉了当时的「应答码」，用户判定"太离谱"） |
| **点名重摆**（`only_labels`，2026-10-03） | 「`plan` 与台账一致、但关卡里那几行被手拖偏了」时**没有只动那几行的路**（默认增量要动 0 行，全量重摆会把 `UEMCP/` 全删了重来） | `execute_build(only_labels=["那几行的 label"])` = **只把这几行按 plan 摆回去**；闸照旧（真跑必须配 `accept_user_edits` + 用户原话），与 `mode="full"` / `adopt` 互斥，**本来就对的行跳过** |
| **微调**（阶段四） | AI 顺手改没被点名的那几行 | 走 `request_plan_change`（**记用户原话**）→ `generate_plan(patch=…)`（**只改点名的那几行**）→ `execute_build(only_labels=[…])`（**只动这几行**）；⚠ **不出图、不要二次确认**，验收 = 用户在 UE 里自己看 + agent 报数字；⚠ 复核期 `plan == 台账` ⇒ 默认增量报「要动 0 行」，**不是**「关卡没问题」——要看现场得先 `evaluate_layout()` |

贯穿全程的三条：**绝不存盘**（存不存由用户在 UE 里定 —— ⚠ **唯一例外是阶段六**：真跑成功后自动存盘，
见上表那格）· **可回滚**（环境台账 + `restore=true`）·
**增量**（改几行就只重摆那几行）。外加一条硬要求：返回数字必须**无损穿过 JSON**
（`-0.0` / `NaN` / `Infinity` 会被 Agent 整条拒收）。

**20 个工具**：`official_status`、`confirm_elements`、`plan_assets`、`rename_assets`、`confirm_assets`、`get_asset_list`、`generate_plan`、`get_plan`、`request_plan_change`、`confirm_plan`、`check_build_target`、`adopt_user_edits`、`execute_build`、`export_layout`、`check_exchange`、`create_surfaces`、`apply_surfaces`、`setup_environment`、`capture_preview`、`evaluate_layout`。

⚠ **2026-10-04 工具面收缩了一次**：原 `generate_build_orders`（plan 米 → 指令表 厘米的**纯翻译件**）**合并进 `execute_build`** —— 它不承载决策、不参与闸门，却和 `execute_build` 读同一份 plan、复用同一条口径。现在它的内核是 `execute_build` 的内部件 `_orders_snapshot()`，由 `execute_build(dry_run=true)` **顺手落一份** `views/build_orders_v1.json` 留痕件（**演练本来就会写留痕，所以这一步零额外副作用**）。

⚠ Agent**不读** MCP 的 `instructions` —— 所以要求要么写在各工具 docstring 里，要么由**代码拒收时的原文**教会调用方。软约束（"你要记得…"）已经踩过坑：能变硬的都变成了代码闸（回读闸 / 规划图闸 / 用户原话 / 改动窗口 / 搭哪张图 / 人工痕迹保护 / **先看现场 G15·G16**）。同一条纪律：**参数不许被静默吞掉** —— `force_full=true` 配上别的 `mode` 现在**直接拒收**（以前被静默忽略，你以为多给了一次确认，其实什么都没发生）。

## 限制与已知缺陷（如实说）

- **必须有 UE + 官方 Unreal MCP 插件**（它固定吃 `127.0.0.1:8000`）。没开 UE 时**只有离线工具能用**：
  `get_plan` / `get_asset_list` / 生成规划 / 画确认图 / 出图**不需要 UE**；找资产 / 验路径 / 落关卡 / 对账**需要**。
- **不出成品图**：它把布局落进你的关卡、贴上材质、配好环境 —— 最终效果**你在 UE 里自己看**，
  它不替你评判"像不像那张参考图"。
- **不替你点确认**：没有"一键闭环""自动确认"，**也不打算做** —— 那会绕过"看图点头"那道闸。
- ✅ **原 D1（`plan_assets` 认不出带分隔符的资产名）已于 2026-09-30 修复并实测** ——
  根因是 `token_match` 拿**整个关键词**去比**单个词**（`MI_Asphalt` 切成 `["mi","asphalt"]`，两边永远对不上）；
  现在按**词序列连续出现**匹配。实测 `plan_assets(["realistic_tree"])` → `found 3 / missing 0`，
  **改之前这两个必报 missing**（证据：`main.py` 的 `[完工-21]` 横幅）。

## 开发 / 跑法

- **DSH** 以 stdio 启动：`command=<根>\.venv\Scripts\python.exe`、`args=[<根>\src\mcp_server\main.py]`；只认 URL 的客户端用 `serve_http.py`，端口 `8770` —— **别抢 8000**，那是官方插件的。
- 改完 `src/mcp_server/main.py` 或规划层：**由用户**跑（⚠ **必须先 `cd` 到仓库根**，或用绝对路径 ——
  下面这条是**相对路径**，只在当前目录正好是仓库根时才找得到）：

  ```powershell
  cd <仓库根>          # 例：cd D:\你的解压目录 —— 少这一句，相对路径就找不到，报错像"预检坏了"
  & .\.venv\Scripts\python.exe tests\preflight.py
  ```

  任何目录都能跑的形式（与 `setup.ps1` 内部用的是同一种，`setup.ps1` 收尾也会把这一行打给你 ——
  下面的 `<仓库根>` 是**占位**，换成你自己的解压目录）：

  ```powershell
  & "<仓库根>\.venv\Scripts\python.exe" "<仓库根>\tests\preflight.py"
  ```

  **必须用脚本方式**（与Agent的启动方式一致）：用 `import mcp_server.main` 会给**假绿**，实测吃过亏。绿了再重启。
- ⚠ **改完代码"重启"后没生效 —— 先看进程，别只看"我重启了"**：`main.py` 改了、跑的却还是旧代码；
  这类问题**不报错**，只表现为"行为像改之前"，最费时间。判据：**进程启动时间**是否晚于**文件修改时间** ——

  ```powershell
  Get-Item .\src\mcp_server\main.py | Select-Object LastWriteTime
  Get-Process python* | Select-Object Id, StartTime, Path
  ```

  要真换掉：**退出Agent（DSH 桌面端）再开**，或用上面的命令确认**确实是新进程**。
- 已知坑（细节都写在代码注释里）：官方连接的取消域跨 task 会**炸掉整个 server**；规划层不能在文件顶部 `from .planning import ...`（脚本方式起必炸）；官方 `find_assets` **不匹配文件夹名**，哈希名资产只能靠"枚举 + 本地按文件夹名匹配"。
- 排障：工具报**没有正文**的错（只有一句 `Error executing tool …`）→ 完整栈在Agent日志 `%APPDATA%\dsh-desktop\logs\harness.log`，搜工具名即可定位。

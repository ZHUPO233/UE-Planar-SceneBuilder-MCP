# 阶段四 · 导出与交换

> 把布局导成一份**与 DCC 无关的场景描述**，方便在 Blender / UE 等之间搬同一套布局。
> 实现 = `export_layout()`（导出）+ `check_exchange()`（回读对账）。⚠ **只读导出**：权威几何永远是 `views/plan_v1.json`。

## 一、原口径 vs 实际落地

**原口径**叫「布局序列化」—— 当天试做的那一版派生件（JSON 主文件 + 统计 + 按 ID 增量更新）**整块回退**了：
阶段一资产表 + 阶段二位置表**已是全局权威**，再做一份派生件属于重复造轮子。

⚠ 同一天晚些时候，**消费者明确了**（「以后方便在 Blender 和 UE 等之间切换」）—— 于是实现成**导出/交换**。

## 二、它做什么

| 工具 | 做什么 |
|---|---|
| `export_layout()` | 落 `views/exchange/scene_v1.json`（机器读）+ `.csv`（表格视图，一行一个物体） |
| `check_exchange()` | 把外部改过的读回来对账（**只出报告、不改 plan**） |

⚠ 导的是**场景描述、不是几何**（官方没有场景导出工具，实测）—— 消费端照着它**重摆一遍**。
⚠ 外部改了这份文件**不会**自动回到 plan：对账报告只告诉你差在哪；要落到 plan 仍走那条既有链 ——
`request_plan_change`（记原话）→ `generate_plan(patch=…)` → **重画图** → `confirm_plan`（看图点头）→ `execute_build()`。

## 三、文件里装什么

**语义 + 尺寸 + 变换 + 材质 + 层**（不是模型）。所以它跨 DCC：Blender 那侧照这份描述重摆即可。

- 工具描述：`main.py` 的 `export_layout()` / `check_exchange()`

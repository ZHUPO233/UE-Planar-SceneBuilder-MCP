⚠ **两条实测结论**（它们决定实现方式，不是推测）：
  ① **环境参数不在 Actor 上，在组件上** —— `ObjectTools.list_properties(DirectionalLight_0)`
     只返回 Actor 级字段加一个 `directionalLightComponent` 引用；雾 / 云同理（`component` /
     `volumetricCloudComponent`）。所以实现必须"**先取组件引用，再在组件上 get/set**"，
     直接对 Actor `set_properties` 是够不着这些参数的。
  ② **这 5 个环境 Actor 是关卡自带的原生 Actor** —— 阶段三按纪律"关卡自带的一个都不碰"
     （清场只清 `UEMCP/` 下我们自己摆的）。两条路线里**用户 2026-09-29 选了 (a)**：
     **复用并改这 5 个原生 Actor** —— 代价是"**改前先记现值 + 可回滚台账**"，已实现成
     `views/environment_state_v1.json` + `setup_environment(restore=true)`。
     (b)「在 `UEMCP/env/` 下另起一套」会与原生那套重叠 / 打架，**没采用**。
     ⚠ 官方**有** `SceneTools.save_actor`，但本工程"**绝不存盘**"的纪律不变 —— 不调它。

**实现（2026-09-29）**：**本阶段的工具 = `setup_environment(preset, factors, overrides, dry_run, restore)`**；
`capture_preview(shots, annotations, dry_run)` 是**同一天做出来的**，但**已划给阶段七**、不算本阶段交付物
（代码保留、实测 3/3、不动用户的视口相机）。时段预设表在 **`config/environments.json`**
（**每次调用都重读**：改它不用改代码、不用重启），5 档：`sunset` / `blue_hour` / `noon` / `night` /
`overcast`（其中 `noon` 记的是**实测现值**，用途是"退回原始环境"）。
出图机位由**世界坐标**推：`yaw = atan2(dy, dx)`、`pitch = atan2(dz, 水平距)`；PNG 落 `views/preview/`（阶段七用）。

⚠ **三条实测结论，已写进代码口径**（不这么做会把用户的状态写坏）：
  ③ **结构体属性是整体替换、不是合并** —— 只写 `atmosphereSunDiskColorScale={"r":0.5}`，
     读回**连合法 JSON 都不是**（没给的 g/b/a 被打坏）→ 一律"先读现值、合并、**整份写**"。
  ④ **`set_actor_transform` 会把没给的字段打到默认值** —— 只传 `rotation`，太阳的 location
     从 `(0,0,400)` 变成 `(0,0,0)`（官方 schema 写的是"未设置=保持不变"，**实测不是**）
     → 改朝向一律**整份传** `location + rotation + scale`。
  ⑤ **云量 / 云密度改不了** —— 实测在**引擎自带**的体积云材质实例上
     （`/Engine/EngineSky/VolumetricClouds/m_SimpleVolumetricCloud_Inst`）：改它就是改引擎资产
     （所有用它的关卡一起变）。能改的只有云的**组件级**参数（层高 / 层厚 / 追踪距离 / 采样）。

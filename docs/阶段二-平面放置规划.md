# 阶段二 · 平面放置规划

**产出** `views/plan_v1.json`（唯一权威，闸门认它）：单位**米**（到 UE 才 ×100）；**一物一行、自带 `pos`、没有 `count`**。段：`world`（中心 / 大小，默认取阶段一「地图大小」）/ `assets[]`（占地 = 阶段一实测包围盒 × `scale`）/ `whiteboxes[]`（`shape` = cube/plane，**cube 必填 `height_m`**；只用阶段一没有可用资产的元素）/ `params` / `confirmation`。

**顺序不能反**：先放已有资产（大小是定的），再放白膜（在剩余空间重估）。坐标由 **agent 看图规划**，**代码不规划坐标、不出图**（图由 AI 拿数据自己画）。

**`scale` 是尺度归一，不是可选项（2026-09-26 加；客户反馈）**：资产**实测尺寸不等于**场景里该有多大 —— 实测 `house1` 只有 **89 cm**、`tree` 有 **1605 cm**，而场景里它们要当十几米的房子、几米的树用。所以资产行**必须按参考图给 `scale`**：`footprint_m` = 实测包围盒 × `scale`（`scale=16` → 89 cm ≈ 14.25 m；`scale=0.31` → 16 m ≈ 5 m）。**偏小 / 偏大是常态，用 `scale` 解决 —— 不许为尺度换资产、更不许拿「这个资产只有 89 cm」去问用户**（该你算的别丢给用户；依据写进该行 `note` 或 plan 的 `params`）。同一元素**可以混用多个模型**（如 `house1` / `house2` 混搭），前提是**都在已确认的清单里** —— 这属于阶段二的规划自由，不必为此单独问一次。

**局部改数据（2026-09-26）**：`generate_plan(patch=[...])` **只发改动的那几行**，不必重发整张表 —— 四种操作 `set` / `add_asset` / `add_whitebox` / `remove`，按 `label` **唯一命中**（找不到或重名都拒收），字段有白名单（资产行不许写 `height_m`，白膜行不许写 `scale`/`asset_path`）。补丁与整表走**同一条**校验 + 落盘 + 归档路径，并在 `params` 里留一条"这一版打了哪几条补丁"。⚠ 补丁与整表不能同时给；第一版必须整表给。

**闸门**：`confirm_plan` 落痕（谁 / 何时 / 哪一版指纹）。未确认不许进第三阶段、不许摆任何东西；坐标 / 占地 / `params` 任一改动 → 指纹不符 → 上次确认自动作废。**数据与图缺一不可且必须一致**：图里要写当前指纹前 10 位，**并覆盖"这一轮该覆盖的行"** —— 2026-09-26 起按**变更集**算（用户要求「局部改就全局部」）：相对上一次确认过的基线只改了 N 行，图里**只需**出现那 N 行的 `label`，没动的行不必重画；**第一次搭（还没有基线）时是全量**（每一行都要出现）。`get_plan().acceptance.change_set` 就是那份清单（`required_labels`）。**位图一律不认账**；不认账的图由代码在落盘时自动清进 `views/archive/`。画前先跑 `python -m mcp_server.planning.plan --figure-checklist`。确认成功时会把**这一版的逐行几何签名**记进台账 `accepted_rows` —— 它就是下一轮算变更集的基线（所以覆盖是传递的：第一版全量画过，之后每轮只画改动过的行）。

⚠ **图的文件名有约定（2026-09-26 加；客户反馈实测）**：图要存成 `views/plan_v1_overview*.svg` —— 代码按这个前缀**找图**（`FIGURE_GLOBS`）。判据是**图的内容**（当前指纹前 10 位 + 该覆盖的行 label），前缀只是找图的约定。客户那头实测：agent 图画对了、名字不合约定，读到的是"views/ 里没有图"，于是**去把文件改了个名** —— 改名**是允许的**（内容对就行），但正确做法是**一开始就按这个名字存**（工具描述与 `get_plan().next_step` 现在都写明）。⚠ 内容不对时改名也过不了，得重画。

**三条代码强制的闸（2026-09-26 加，把软约束变硬）**：① **改完必须回读** —— 每次写盘都在台账挂一条"待回读"（`get_plan().acceptance.awaiting_readback`），**没调 `get_plan()` 之前，`generate_plan` 与 `execute_build` 一律拒收**（拒收信息里逐行摆出这一版改了什么）。② **阶段一没走完不许规划** —— 没有 `catalog/asset_list.json`（签过字的资产清单）时 `generate_plan` 直接拒收（空表初始化态除外）。③ **证据链（堵最大的那个洞）** —— 图是 agent 画的、确认是它调的，所以 `confirm_plan` **必须带 `user_quote`（用户点头的原话）**，且那张图**出炉 ≥ `MIN_CONFIRM_DELAY_S`（15 秒，可调）**才准确认；`execute_build` 落地前再核一次"这句原话在不在"，没有就拒收。实测被绕过一次：agent 自己画图、自己确认、直接开摆，客户当场质问「图都不先让我确认就摆」。

**第四条：「改动窗口」闸（2026-09-26 加；**尚未实测**）** —— 客户 Agent 交付后自评点名的那条「用户提改动要调 `request_plan_change` —— **一次都没调过**，你每次说要改，我直接 patch，没走变更台账」。规则：一份规划**被确认过之后**（台账里有 `accepted_rows`），要再改**内容**，必须先留下「改什么 / 谁要的」—— `request_plan_change(items=[...], by=...)` 打开「改动窗口」（`get_plan().acceptance.change_window_open`），`confirm_plan()` 关上它，所以一轮里可以连着改多次。窗口关着就改（`patch` 或整表）→ `generate_plan` **拒收，一个字节都不写**。**原样重发同一份数据不受影响**（指纹没变）。⚠ 这不是"要等用户开口"：自查修正也要记一条（`by="agent 自查"`）—— 要的是那层**对应关系**，好让台账事后答得了「用户说了什么 ↔ 数据变成什么」。实现：`planning.plan.record_change_request()` / `record_acceptance()` + `main.py` 的 `_change_request_guard()`。

⚠ **阶段二有且只有一条检查：越界**（2026-09-27 用户指令：「只有一个检查，是否有物体超出世界边界」）—— 实现是 `planning/plan.py` 的 `bounds_check()` / `bounds_check_text()`：判**中心**与**占地四角**是否都在 `world.bounds` 内（含边界，1e-6 容差；超出量按米报出来、按超得多到少排）。**只报红、不拦**（越界不是错误，是"你得知道这件事"），而且**绝不写进 plan** —— 写进去会改几何指纹、把上一次确认无谓作废。⚠ **判据分三级**（2026-09-27 用户要求「关于你的判断进行完善」，实现是 `planning/plan.py` 的 `BOUNDS_TIERS`）：**硬 · 实体**（`house` / `tree` / `shrub`，**以及表里没有的一切 element_key**）四角必须都在界内 —— 压线 = 半截悬空、树冠探到世界外；**软 · 铺装**（`road` / `sidewalk` / `path` / `grass`）**允许贴边、不许超出**（它们铺在世界地基上）；**豁免 · 边界元素**（`ground`）**它自己就是世界边界**，四角正好压线合法（超出仍报）。依据：加了世界地基之后 `world.bounds` **就等于地基的范围**，"越界"的物理含义是**跑到地基外面 = 悬空 / 穿帮** —— 所以**没有哪一类"可以越界"**，只有"允许贴边"与"必须完整在界内"之分。⚠ **不给植物开后门**：树冠"探出去一点"看着自然，但一旦按类开口子，这条检查就没有一致判据了 —— 要让树冠出界就**把世界放大**。报告里**硬在前、软在后**，同级按越界米数从大到小排。⚠ 判据把 `footprint_m` 当**世界轴对齐尺寸**用、**不叠 `rot_deg`**（plan 的 `params` 写明它是"旋转之后的世界 X / Y 占地"，再叠一次就是转两遍）；代价是：若某行 `rot_deg != 0` 而 footprint 其实是未旋转的，这条会**少报**。11 项具名自检**仍不回来**（2026-09-25 删，它们在替人做决定）；**碰撞检测与布局修正已整段删除**（2026-09-27：重叠**不检、不修**）。旧 `checks` 不再读、也不动（参与那版指纹）。仍有效的形状校验：白膜留空 `asset_path` + 写 `shape` + 写明"预估"；资产必须有 `asset_path` + `scale > 0`。

状态 `initialized` / `draft` / `confirmed` 只由 `get_plan` 现算；每版覆盖前自动留档。坐标系：左手系 Z-up，X 前进 / Y 右 / Z 上。

# 阶段二 · 平面放置规划

**产出** `views/plan_v1.json`（唯一权威，闸门认它）：单位**米**（到 UE 才 ×100）；**一物一行、自带 `pos`、没有 `count`**。段：`world`（中心 / 大小，默认取阶段一「地图大小」）/ `assets[]`（占地 = 阶段一实测包围盒 × `scale`；**选填 `scale_z`** = **Z 方向倍率**，只拉高 / 压低、**占地一个数都不动** —— 要「楼别一样高、但街道布局不变」就用它，改 `scale` 是整体缩放、占地会跟着变）/ `whiteboxes[]`（`shape` = cube/plane，**cube 必填 `height_m`**；只用阶段一没有可用资产的元素）/ `params` / `confirmation`。

**顺序不能反**：先放已有资产（大小是定的），再放白膜（在剩余空间重估）。坐标由 **agent 看图规划**，**代码不规划坐标、不出图**（图由 AI 拿数据自己画）。

**`scale` 是尺度归一，不是可选项（2026-09-26 加；客户反馈）**：资产**实测尺寸不等于**场景里该有多大 —— 实测 `house1` 只有 **89 cm**、`tree` 有 **1605 cm**，而场景里它们要当十几米的房子、几米的树用。所以资产行**必须按参考图给 `scale`**：`footprint_m` = 实测包围盒 × `scale`（`scale=16` → 89 cm ≈ 14.25 m；`scale=0.31` → 16 m ≈ 5 m）。**偏小 / 偏大是常态，用 `scale` 解决 —— 不许为尺度换资产、更不许拿「这个资产只有 89 cm」去问用户**（该你算的别丢给用户；依据写进该行 `note` 或 plan 的 `params`）。同一元素**可以混用多个模型**（如 `house1` / `house2` 混搭），前提是**都在已确认的清单里** —— 这属于阶段二的规划自由，不必为此单独问一次。

**局部改数据（2026-09-26）**：`generate_plan(patch=[...])` **只发改动的那几行**，不必重发整张表 —— 四种操作 `set` / `add_asset` / `add_whitebox` / `remove`，按 `label` **唯一命中**（找不到或重名都拒收），字段有白名单（资产行不许写 `height_m`，白膜行不许写 `scale`/`asset_path`）。补丁与整表走**同一条**校验 + 落盘 + 归档路径，并在 `params` 里留一条"这一版打了哪几条补丁"。⚠ 补丁与整表不能同时给；第一版必须整表给。

**闸门**：`confirm_plan` 落痕（谁 / 何时 / 哪一版指纹）。未确认不许进第三阶段、不许摆任何东西；坐标 / 占地 / `params` 任一改动 → 指纹不符 → 上次确认自动作废。**数据与图缺一不可且必须一致**：图里要写当前指纹前 10 位，**并覆盖"这一轮该覆盖的行"** —— 2026-09-26 起按**变更集**算（用户要求「局部改就全局部」）：相对上一次确认过的基线只改了 N 行，图里**只需**出现那 N 行的 `label`，没动的行不必重画；**第一次搭（还没有基线）时是全量**（每一行都要出现）。`get_plan().acceptance.change_set` 就是那份清单（`required_labels`）—— **要出哪几张图见同一处的 `required_views`**（2026-09-30 加：**位移 / 朝向 → 顶视图；大小 / 高度 → 「原图视角」透视示意图**，见下面那条）。**位图一律不认账**；不认账的图由代码在落盘时自动清进 `views/archive/`（平面图与立面图**两路都清**）。画前先跑 `python -m mcp_server.planning.plan --figure-checklist`。确认成功时会把**这一版的逐行几何签名**记进台账 `accepted_rows` —— 它就是下一轮算变更集的基线（所以覆盖是传递的：第一版全量画过，之后每轮只画改动过的行）。

⚠ **图有两种，可能要出两张（2026-09-30 加；用户要求）** —— 前缀是**代码找图的约定**（`FIGURE_GLOBS` / `ELEVATION_GLOBS`），判据永远是**图的内容**（当前几何指纹前 10 位 + 该覆盖的行 label）：
  · **平面图**（俯视）→ `views/plan_v1_overview*.svg`；
  · **立面图**（正视图 X 向 / 侧视图 Y 向）→ `views/plan_v1_elevation*.svg`。

**每一版都出两张图**（**2026-09-30 用户定案** —— 先做过"按动的是哪一维决定出哪几张"，当天定为恒出两张。用户原话：「算了直接生成「原图视角」透视示意图和顶视图算了，太麻烦了」）：

| 图 | 画哪个平面 | 存成 | 看什么 |
|---|---|---|---|
| **顶视图** | **X-Y**（俯视） | `views/plan_v1_overview*.svg` | 摆在哪 / 占地多大（含朝向） |
| **「原图视角」透视示意图** | **透视：近大远小** | `views/plan_v1_elevation*.svg` | 多高 / 多大（体量） |

**为什么恒出两张**（常量在 `planning/plan.py` 的 `REQUIRED_VIEWS`）：① **少一类往返失败** —— 条件视图的失败模式是"判错维度 → 要的那张没画 → `confirm_plan` 拒收 → 再画一遍"；② **规则少一条**（常量不必向 agent 解释，也少一处"文档与代码分叉"）。代价只有多画一张 svg。
⚠ **"原图视角" = 沿 X 看**：本工程坐标系 `world.coordinate_system` 定的是 **X 前进**（承载参考图的纵深链）⇒ 屏幕上剩下 Y（右）与 Z（上）。
⚠ 它是**透视示意图**（近大远小）—— **每行必须标 `x_m`**、**被挡住的行也必须出图**；给你核对体量 / 高度 / **谁在前谁在后**用，**不是严格投影**。
⚠ `change_set.changed_dims` 仍然在（说清"这一版动了哪一维"），但它**只用来决定图里重点标哪几行**，**不再决定出哪几张图**。

⚠ **画图直接用 `get_plan().drawing`（2026-09-30 加）**：每行带 `x_m` / `y_m` / `z_base_m` / `z_top_m` / `w_m` / `d_m` / `h_m`（**米**），Z 口径**与阶段三同源**（`_compose_build_rows()`）—— **别自己推 Z**（推错就是两套口径 = 图与数据不一致 = 等于没确认）。它是**只读派生值**：不写进 `plan_v1.json`、**不进几何指纹**。取不到实测包围盒的行 `z_top_m` 给 `null` 并**如实报**（不拿别的数顶替）。

⚠ **改名是允许的，但一开始就该按约定命名**（2026-09-26 客户反馈实测）：agent 图画对了、名字不合约定，读到的是"views/ 里没有**那一路**的图"，于是**去把文件改了个名** —— 内容对就认账，但正确做法是**一开始就按前缀存**（工具描述与 `get_plan().next_step` 现在都写明）。⚠ 内容不对时改名也过不了，得重画。画前先跑 `python -m mcp_server.planning.plan --figure-checklist`（它会打印"要出哪几张图 + 每张图要出现哪些行"）。

**三条代码强制的闸（2026-09-26 加，把软约束变硬）**：① **改完必须回读** —— 每次写盘都在台账挂一条"待回读"（`get_plan().acceptance.awaiting_readback`），**没调 `get_plan()` 之前，`generate_plan` 与 `execute_build` 一律拒收**（拒收信息里逐行摆出这一版改了什么）。② **阶段一没走完不许规划** —— 没有 `catalog/asset_list.json`（签过字的资产清单）时 `generate_plan` 直接拒收（空表初始化态除外）。③ **证据链（堵最大的那个洞）** —— 图是 agent 画的、确认是它调的，所以 `confirm_plan` **必须带 `user_quote`（用户点头的原话）**，且那张图**出炉 ≥ `MIN_CONFIRM_DELAY_S`（15 秒，可调）**才准确认（⚠ 2026-09-30 起：认账的图可能**不止一张**，判据取**最新画好的那张** —— 要确认，每一张都得等够时间）；`execute_build` 落地前再核一次"这句原话在不在"，没有就拒收。实测被绕过一次：agent 自己画图、自己确认、直接开摆，客户当场质问「图都不先让我确认就摆」。

**第四条：「改动窗口」闸（2026-09-26 加；**尚未实测**）** —— 客户 Agent 使用后自评点名的那条「用户提改动要调 `request_plan_change` —— **一次都没调过**，你每次说要改，我直接 patch，没走变更台账」。规则：一份规划**被确认过之后**（台账里有 `accepted_rows`），要再改**内容**，必须先留下「改什么 / 谁要的」—— `request_plan_change(items=[...], by=...)` 打开「改动窗口」（`get_plan().acceptance.change_window_open`），`confirm_plan()` 关上它，所以一轮里可以连着改多次。窗口关着就改（`patch` 或整表）→ `generate_plan` **拒收，一个字节都不写**。⚠ **原来这里写着「原样重发同一份数据不受影响（指纹没变）」—— 2026-09-30 实测证明这句是错的，已改**：`params` **在几何指纹里**（`plan_geometry_hash()` 只排除 `confirmation`），而 `generate_plan` **每次都会往 `params` 写一条**「本版变更（补丁）：按 label 打了 1 条补丁…」。所以**重发一条值一模一样的补丁，指纹也会变**：实测 r35 → r36 几何一个数没改，指纹 `a3b86f97e4…` → `700566b5bf…`（因为补丁说明从「`0.175 → 0.185`」变成「`0.185 → 0.185`」），**上一版确认与旧图随之作废**（`plan_v1_overview_r35.svg` 被自动归档）。同一次实测也证实了另一半：**几何确实幂等** —— r36 重新确认后 `execute_build(dry_run=true)` → `要删 []` / `要摆 []` / `没动 7`，**且全程一个 Actor 都没动**。所以"幂等"要**分两半说**：**几何幂等 / 指纹与确认不幂等**。⚠ "任何一次落盘都会关闸"来自 `planning/plan.py` 的 `build_plan()` —— 它把 `confirmation.confirmed` **硬编码成 False**，而补丁路与整表路**都**经它 → **设计如此、fail-closed，不是 bug**；错的只是这句描述。⚠ 这不是"要等用户开口"：自查修正也要记一条（`by="agent 自查"`）—— 要的是那层**对应关系**，好让台账事后答得了「用户说了什么 ↔ 数据变成什么」。实现：`planning.plan.record_change_request()` / `record_acceptance()` + `main.py` 的 `_change_request_guard()`。

⚠ **阶段二有且只有一条检查：越界**（2026-09-27 用户指令：「只有一个检查，是否有物体超出世界边界」）—— 实现是 `planning/plan.py` 的 `bounds_check()` / `bounds_check_text()`：判**中心**与**占地四角**是否都在 `world.bounds` 内（含边界，1e-6 容差；超出量按米报出来、按超得多到少排）。**只报红、不拦**（越界不是错误，是"你得知道这件事"），而且**绝不写进 plan** —— 写进去会改几何指纹、把上一次确认无谓作废。⚠ **判据分三级**（2026-09-27 用户要求「关于你的判断进行完善」，实现是 `planning/plan.py` 的 `BOUNDS_TIERS`）：**硬 · 实体**（`house` / `tree` / `shrub`，**以及表里没有的一切 element_key**）四角必须都在界内 —— 压线 = 半截悬空、树冠探到世界外；**软 · 铺装**（`road` / `sidewalk` / `path` / `grass`）**允许贴边、不许超出**（它们铺在世界地基上）；**豁免 · 边界元素**（`ground`）**它自己就是世界边界**，四角正好压线合法（超出仍报）。依据：加了世界地基之后 `world.bounds` **就等于地基的范围**，"越界"的物理含义是**跑到地基外面 = 悬空 / 穿帮** —— 所以**没有哪一类"可以越界"**，只有"允许贴边"与"必须完整在界内"之分。⚠ **不给植物开后门**：树冠"探出去一点"看着自然，但一旦按类开口子，这条检查就没有一致判据了 —— 要让树冠出界就**把世界放大**。报告里**硬在前、软在后**，同级按越界米数从大到小排。⚠ 判据把 `footprint_m` 当**世界轴对齐尺寸**用、**不叠 `rot_deg`**（plan 的 `params` 写明它是"旋转之后的世界 X / Y 占地"，再叠一次就是转两遍）；代价是：若某行 `rot_deg != 0` 而 footprint 其实是未旋转的，这条会**少报**。11 项具名自检**仍不回来**（2026-09-25 删，它们在替人做决定）；**碰撞检测与布局修正已整段删除**（2026-09-27：重叠**不检、不修**）。旧 `checks` 不再读、也不动（参与那版指纹）。仍有效的形状校验：白膜留空 `asset_path` + 写 `shape` + 写明"预估"；资产必须有 `asset_path` + `scale > 0`。

状态 `initialized` / `draft` / `confirmed` 只由 `get_plan` 现算；每版覆盖前自动留档。坐标系：左手系 Z-up，X 前进 / Y 右 / Z 上。

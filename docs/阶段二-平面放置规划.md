# 阶段二 · 平面放置规划

**产出** `views/plan_v1.json`（纪元 1；**纪元 2 起是 `views/plan_v2.json`** —— 哪份算数只看 `planning.active_plan_path()`，见 `AGENTS.md`「纪元」那一节）：单位**米**（到 UE 才 ×100）；**一物一行、自带 `pos`、没有 `count`**。段：`world`（中心 / 大小，默认取阶段一「地图大小」）/ `assets[]`（占地 = 阶段一实测包围盒 × `scale`；**选填 `scale_z`** = **Z 方向倍率**，只拉高 / 压低、**占地一个数都不动** —— 要「楼别一样高、但街道布局不变」就用它，改 `scale` 是整体缩放、占地会跟着变；**`z_m` 必填**，见下）/ `whiteboxes[]`（`shape` = cube/plane；⚠ **`height_m` 必填、必须 > 0，`plane` 也不例外** —— 官方 `PrimitiveTools` 只有 cube / cone / cylinder / sphere，**没有 plane 工具**，所以「面」落进 UE 也只能是 cube；阶段一清单里 plane 那行的 `size_cm[2]=0` 是**登记习惯**、不是厚度。只用阶段一没有可用资产的元素）/ `params` / `confirmation`。

> ⚠ **`z_m` = 底面标高（2026-10-07 用户定案 B）**：两种行**同一个量** —— **这东西坐在多高**（米、绝对标高）。
> **必填**（2026-10-08 起 · 用户指令「赶紧改位置表结构增加Z」）：**Z 只在表里** —— 阶段三只读这一行的
> `z_m`，**不再**按 `element_key` 查表推（那张 `WHITEBOX_VERTICAL` 已删）。参照值：路面上的 `0.00`、
> 站在两侧地面上的 `0.15`、人行道底面贴路面 `0.00`、世界地基 `−0.05`、车行道 `−0.15`。
> ⚠ **改之前是两种口径**：资产行按「**Actor 原点**标高」、白膜行按「**中心**标高」—— 使用者得自己减
> `height_m/2`、或去查那张 pivot 表，**减错就是东西浮在半空**（阶段四「白膜比地面高 15 cm」那个 bug 就是这么来的）。
> ⚠ 本层**不做 Z 换算**（只存这个数）—— 推中心 / 原点的**只有阶段三那一处**（`_compose_build_rows()`）。
> ⚠ `get_plan().drawing` 段**已删除**（原来它才带 `z_base_m` / `z_top_m`）—— 见下面「`drawing` 段已删除」那条。

**顺序不能反**：先放已有资产（大小是定的），再放白膜（在剩余空间重估）。坐标由 **agent 规划**（**代码不规划坐标**）。
⚠ **图由代码出**（不是 agent 画）：落盘那一刻自动生成一页 three.js —— 见下面「出图口径」那一节。

**`scale` 是尺度归一，不是可选项（2026-09-26 加；客户反馈）**：资产**实测尺寸不等于**场景里该有多大 —— 实测 `house1` 只有 **89 cm**、`tree` 有 **1605 cm**，而场景里它们要当十几米的房子、几米的树用。所以资产行**必须按参考图给 `scale`**：`footprint_m` = 实测包围盒 × `scale`（`scale=16` → 89 cm ≈ 14.25 m；`scale=0.31` → 16 m ≈ 5 m）。**偏小 / 偏大是常态，用 `scale` 解决 —— 不许为尺度换资产、更不许拿「这个资产只有 89 cm」去问用户**（该你算的别丢给用户；依据写进该行 `note` 或 plan 的 `params`）。同一元素**可以混用多个模型**（如 `house1` / `house2` 混搭），前提是**都在已确认的清单里** —— 这属于阶段二的规划自由，不必为此单独问一次。

**局部改数据（2026-09-26）**：`generate_plan(patch=[...])` **只发改动的那几行**，不必重发整张表 —— 四种操作 `set` / `add_asset` / `add_whitebox` / `remove`，按 `label` **唯一命中**（找不到或重名都拒收），字段有白名单（资产行不许写 `height_m`，白膜行不许写 `scale`/`asset_path`）。补丁与整表走**同一条**校验 + 落盘 + 归档路径，并在 `params` 里留一条"这一版打了哪几条补丁"。⚠ 补丁与整表不能同时给；第一版必须整表给。

**闸门**：`confirm_plan` 落痕（谁 / 何时 / 哪一版指纹）。未确认不许进第三阶段、不许摆任何东西；坐标 / 占地 / `params` 任一改动 → 指纹不符 → 上次确认自动作废。**数据与页缺一不可且必须一致**（⚠ **这条闸只管前三阶段 / 阶段二验收**；**四 · 微调那一版不出图**、也不走 `confirm_plan`，见下）：**页的正文里要写当前几何指纹前 10 位**，**并覆盖"这一轮该覆盖的行"** —— 2026-09-26 起按**变更集**算（用户要求「局部改就全局部」）：相对上一次确认过的基线只改了 N 行，页里**只需**出现那 N 行的 `label`，没动的行不必再出现；**第一次搭（还没有基线）时是全量**（每一行都要出现）。`get_plan().acceptance.change_set` 就是那份清单（`required_labels`）—— **要出哪一张见同一处的 `required_views`**（2026-10-11 起**恒为一张**：`REQUIRED_VIEWS = ["page"]`，见下面「出图口径」）。**位图与旧格式一律不认账**；那一页**由代码在落盘时自动重生成**，所以 `views/` 下不会有"别的版本生成的页"（自动清图那套已删，见下）。想人工抽查"这一版该覆盖哪些行"，可以跑 `python -m mcp_server.planning.plan --figure-checklist`（⚠ 它现在**只是人工抽查用** —— 页由代码生成、自检在**落盘那一刻**就跑，不再是"画图前照抄清单"）。确认成功时会把**这一版的逐行几何签名**记进台账 `accepted_rows` —— 它就是下一轮算变更集的基线（所以覆盖是传递的：第一版全量出现过，之后每轮只需出现改动过的行）。

⚠ **纪元 2 开了之后 `views/plan_v1.json` 冻结只读**（2026-10-04 加；见 `AGENTS.md` 的「纪元（epoch）」那一节）：阶段三**整批落地**（`mode` 解析为 `full`）时**自动换纪元、再当场落位**（2026-10-15 改：**不再需要用户先说一句话**；`confirm_stage3` 只是手工旁路）（2026-10-12 改：不再有"另一次只做切换、一个 Actor 都不动"的调用）—— 权威几何移交 `views/plan_v2.json`（整表照抄，几何指纹**逐位不变**），台账整表接力成 `views/build_state_v2.json`，**资产表逐字节照抄成 `catalog/asset_list_v2.json`**，v1 只作留档（`confirmation.frozen_at` / `frozen_by=epoch2`）。⚠ **不可逆**：落进关卡之后**回不到前三阶段**，此后任何往 `plan_v1.json` 的写一律拒收（拒收原文「拒收：**纪元 1 已结束，`plan_v1.json` 冻结只读** —— 一个字节都没写。」）。**阶段二这一整套闸（那一页 + `confirm_plan` 看图点头 + 变更集）只管纪元 1**；纪元 2 之后改行走「四 · 微调」那条（`request_plan_change` → `generate_plan(patch=…)` → `execute_build(only_labels=[…])`，**不画图、不重确认**）。⚠ 全工程读 plan 只认**一个咽喉**：`planning.active_plan_path()` / `active_plan()` / `active_epoch()`—— **判据只有一条：「`plan_v2.json` 在 ⇒ 永远是它；不在 ⇒ 才轮到 `plan_v1.json`」**（**没有"能不能解析"那一层**；v2 一旦在，读不动也**不退回** v1）。资产表同一条判据：`planning.active_asset_list_path()`（`asset_list_v2.json` 在 ⇒ 就它；不在 ⇒ 纪元 1 的 `asset_list.json`；⚠ `surfaces.py` 里有一份同形实现，两处必须同时改）。—— 别在别处各拼一次路径；写盘仍只有 `planning.write_plan()`（`target` 默认 = 活动那份，**归档名带纪元前缀** `plan_v1_<戳>_<confirmed|draft>.json` / `plan_v2_…`，v1 / v2 不会互相覆盖）。

### 出图口径：**一页 three.js，由代码自动出**（2026-10-12 重写）

⚠ **每一版出一页 three.js，而且由代码自动出**（用户原话：「整改2阶段，不出图，出three.js」）：
  · **文件** = `views/<plan 名>_view.html`（`plan_v1.json` → `views/plan_v1_view.html`；纪元 2 → `views/plan_v2_view.html`）——
    命名约定来自 `FIGURE_GLOBS = ("plan_*_view.html", "plan_*_view.htm")`；**判据永远是页的内容**；
  · **由 `write_plan()` 在落盘那一刻自动生成**（`planning/figure3d.py` + `planning/web/preview3d.html`）
    —— **Agent 不用去画任何东西**，也**不许**再手画。⚠ 页**没出来时也别去手画**：看落盘那次报文的
    `plan_view.errors`（原因逐条列出），或手工重出 `python -m mcp_server.planning.figure3d`；
  · **它是一张能转、能缩、能点的页**：页上的机位按钮有 **4 个**（`#bar` 里）—— **斜视角** / **沿街侧视** / **顶视图** / **原图视角**（另有「重置」与两个勾选框：全部标签 / 网格）。

**要出哪一张**（常量 `planning/plan.py` 的 `REQUIRED_VIEWS`）：**恒为一张 —— `["page"]`**（2026-10-11 用户定案）。
⚠ 取值是 `"page"` 而**不是** `"top"`：它既不是顶视图也不是立面图 —— 它是一张**能转的页**，名字照实写。
⚠ **当年"要两张"的理由已经不成立**：2026-09-30 定的是**恒出两张 agent 手绘矢量图**
（`top` 顶视图 + `elevation` 原图视角透视），理由是"只动高度时顶视图看不出高低"。现在那一页**转一下、
或按页上的「原图视角」按钮**就看得见 ⇒ 一张就够。**那套手绘机制已整套删除**（`plan_wire_v1.png` /
`plan_render.py` / `png.py` / `views/plan_v1_overview*.svg` / `views/plan_v1_elevation*.svg` 这一类产物名
**已作废**，`ELEVATION_GLOBS` 也已删除）—— **别再按它讲**。

| 页上的视角 | 看哪个平面 | 看什么 |
|---|---|---|
| **斜视角** | 3/4 透视 | 整体关系（页的默认机位） |
| **沿街侧视** | 立面 | 高度变了没有（**Z 变了只有立面视角看得出来**） |
| **顶视图** | **X-Y**（俯视） | 摆在哪 / 占地多大（含朝向） |
| **原图视角** | **沿 X 看**（透视，近大远小） | 多高 / 多大（体量）、谁在前谁在后 |

⚠ **"原图视角" = 沿 X 看**：本工程坐标系 `world.coordinate_system` 定的是 **X 前进**（承载参考图的纵深链）⇒ 屏幕上剩下 Y（右）与 Z（上）。它是**透视示意图**（近大远小），**不是严格投影**。
⚠ **顶视图上还要有「原图视角」这条箭头的文字**（2026-10-04 用户要求：「生成顶视图加个原图视角箭头，不然用户看不懂」）：俯视时**看不出哪边是「原图往里看」的方向**，所以页的 3D 场景里画一条**沿 +X** 的箭头、旁边写上 `原图视角（相机沿 +X 看）`（**一字不差**）。⚠ **位置与朝向以 `planning/plan.py` 的 `origin_view_spec()` 为准**（`arrow_from_m` → `arrow_to_m`，米、世界坐标；`label` = 要写的字；`where` = 放哪儿：**图框下沿、世界范围之外**（世界 Y 最小边再往外 `ORIGIN_VIEW_ARROW_GAP_M` = 2 m），别压到任何一行）—— **别自己摆**（与"别自己推 Z"同一条纪律：口径只能有一份）。箭头**横贯整幅、指向 +X**：X 取世界最小边 → 最大边。⚠ 页里由 `web/preview3d.html` 的 `buildOriginArrow()` / `buildOriginLabel()` 画；`origin_view_spec()` 只服务"缺这四个字记一条提示"与人工核对，**不再指挥谁去画图**。⚠ **缺这条只提示、不拒收**（2026-10-04 定的"第一版只报不拦"）：该页 verdict 的 `warnings` 记 `ORIGIN_VIEW_MISSING_WARNING`（「顶视图缺「原图视角」箭头 —— 用户会看不懂朝向」），`figure_check().warnings` 汇总带出来；**确认闸门与既有判据一个字没变**。相关常量：`ORIGIN_VIEW_LABEL` / `ORIGIN_VIEW_ARROW_GAP_M` / `ORIGIN_VIEW_MISSING_WARNING`（跑 `--figure-checklist` 也会把箭头坐标与文字一起打出来）。
**认账判据**（`planning/plan.py::figure_verdicts()`，**唯一一处**）：**页正文里有当前几何指纹前 10 位** + **该覆盖的每一行 `label`**（`change_set().required_labels`；比对时去掉全部空白，且命中处后面不能紧跟数字 —— 免得 `停放车辆 #1` 被 `停放车辆 #10` 假命中）。**位图（png / jpg / jpeg / webp / gif）与旧格式一律不认账**：位图读不出文字 ⇒ 核验不了"漏没漏行"。
⚠ **页生成失败不拦落盘**（判据分开报："plan 写成了没有" 与 "页出没出来" 是两件事）：落盘是别的所有阶段的输入，为了一张预览页把 plan 挡在门外不划算。失败原因在落盘报文的 `plan_view.errors` 里逐条列出。

⇒ `views/` 下不可能有"别的版本生成的页"**。（落盘报文里 `removed_figures` / `kept_figures` 两个键
**保留但恒为空** —— 不改调用方，空表就是如实答案。）

**三条代码强制的闸（2026-09-26 加，把软约束变硬）**：① **改完必须回读** —— 每次写盘都在台账挂一条"待回读"（`get_plan().acceptance.awaiting_readback`），**没调 `get_plan()` 之前，`generate_plan` 与 `execute_build` 一律拒收**（拒收信息里逐行摆出这一版改了什么）。② **阶段一没走完不许规划** —— 没有签过字的资产清单时 `generate_plan` 直接拒收（空表初始化态除外；⚠ 读的是**活动那份资产表** = `planning.active_asset_list_path()`，纪元 1 是 `catalog/asset_list.json`、纪元 2 是 `catalog/asset_list_v2.json` —— **不是写死 v1 那个路径**）。③ **证据链（堵最大的那个洞）** —— 确认必须有人真的看过那一页，所以 `confirm_plan` **必须带 `user_quote`（用户点头的原话）**，且那一页**生成 ≥ `MIN_CONFIRM_DELAY_S`（5 秒）**才准确认（⚠ 落盘即生成，所以这道下限判的是**你有没有把它交给用户** —— 刚重落盘就自己确认 = 没人看过；**2026-10-11 起认账的页恒为一张**，判据取**最新那份认账的页**）；`execute_build` 落地前再核一次"这句原话在不在"，没有就拒收。⚠ **由来（历史实测）**：这一条是"agent 自己画图、自己确认、直接开摆"逼出来的 —— 客户当场质问「图都不先让我确认就摆」。**现在页由代码生成，但"确认是人的动作"这一层一点没松**。⚠ **这一条只管前三阶段 / 阶段二验收** —— **四 · 微调那一版没有图**，它的凭据是 `request_plan_change` 里用户的**原话** + `only_labels` 点名（`planning.mark_tuned()` 写的 `confirmation.mode = "tuned"`），**不适用这条看图闸**。

**第四条：「改动窗口」闸（2026-09-26 加；**尚未实测**）** —— 客户 Agent 使用后自评点名的那条「用户提改动要调 `request_plan_change` —— **一次都没调过**，你每次说要改，我直接 patch，没走变更台账」。规则：一份规划**被确认过之后**（台账里有 `accepted_rows`），要再改**内容**，必须先留下「改什么 / 谁要的」—— `request_plan_change(items=[...], by=...)` 打开「改动窗口」（`get_plan().acceptance.change_window_open`），`confirm_plan()` 关上它，所以一轮里可以连着改多次。窗口关着就改（`patch` 或整表）→ `generate_plan` **拒收，一个字节都不写**。⚠ **原来这里写着「原样重发同一份数据不受影响（指纹没变）」—— 2026-09-30 实测证明这句是错的，已改**：`params` **在几何指纹里**（`plan_geometry_hash()` 只排除 `confirmation`），而 `generate_plan` **每次都会往 `params` 写一条**「本版变更（补丁）：按 label 打了 1 条补丁…」。所以**重发一条值一模一样的补丁，指纹也会变**：实测 r35 → r36 几何一个数没改，指纹 `a3b86f97e4…` → `700566b5bf…`（因为补丁说明从「`0.175 → 0.185`」变成「`0.185 → 0.185`」），**上一版确认与旧图随之作废**（当时的工程图 `plan_v1_overview_r35.svg` 被自动归档 —— ⚠ 那是**手画那套**的产物名，那套已删，现在的产物是 `views/<plan 名>_view.html`）。同一次实测也证实了另一半：**几何确实幂等** —— r36 重新确认后，`execute_build` 的第 ①.5 步（内部件 `_orders_snapshot()`，**真跑也走**）算出 `要删 []` / `要摆 []` / `没动 7` —— **不碰关卡**，且全程一个 Actor 都没动。所以"幂等"要**分两半说**：**几何幂等 / 指纹与确认不幂等**。⚠ "任何一次落盘都会关闸"来自 `planning/plan.py` 的 `build_plan()` —— 它把 `confirmation.confirmed` **硬编码成 False**，而补丁路与整表路**都**经它 → **设计如此、fail-closed，不是 bug**；错的只是这句描述。⚠ 这不是"要等用户开口"：自查修正也要记一条（`by="agent 自查"`）—— 要的是那层**对应关系**，好让台账事后答得了「用户说了什么 ↔ 数据变成什么」。实现：`planning.plan.record_change_request()` / `record_acceptance()` + `main.py` 的 `_change_request_guard()`。

⚠ **阶段二有且只有一条检查：越界**（2026-09-27 用户指令：「只有一个检查，是否有物体超出世界边界」）—— 实现是 `planning/plan.py` 的 `bounds_check()` / `bounds_check_text()`：判**中心**与**占地四角**是否都在 `world.bounds` 内（含边界，1e-6 容差；超出量按米报出来、按超得多到少排）。**只报红、不拦**（越界不是错误，是"你得知道这件事"），而且**绝不写进 plan** —— 写进去会改几何指纹、把上一次确认无谓作废。⚠ **判据分三级**（2026-09-27 用户要求「关于你的判断进行完善」，实现是 `planning/plan.py` 的 `BOUNDS_TIERS`）：**硬 · 实体**（`house` / `tree` / `shrub`，**以及表里没有的一切 element_key**）四角必须都在界内 —— 压线 = 半截悬空、树冠探到世界外；**软 · 铺装**（`road` / `sidewalk` / `path` / `grass`）**允许贴边、不许超出**（它们铺在世界地基上）；**豁免 · 边界元素**（`ground`）**它自己就是世界边界**，四角正好压线合法（超出仍报）。依据：加了世界地基之后 `world.bounds` **就等于地基的范围**，"越界"的物理含义是**跑到地基外面 = 悬空 / 穿帮** —— 所以**没有哪一类"可以越界"**，只有"允许贴边"与"必须完整在界内"之分。⚠ **不给植物开后门**：树冠"探出去一点"看着自然，但一旦按类开口子，这条检查就没有一致判据了 —— 要让树冠出界就**把世界放大**。报告里**硬在前、软在后**，同级按越界米数从大到小排。⚠ 判据把 **`footprint_m` 当"物体自身的 [宽, 深]"**用，并 **按 `rot_deg` 把四角转过去**再比世界边界（**2026-10-07 修**）—— 它与阶段三交给 cube 的 `size_cm` **同源**，`rot_deg` 就是那之后绕 Z 的 yaw。⚠ 原来这里**不叠 `rot_deg`**，理由是"`params` 写明 footprint 是旋转后的世界 X / Y 占地"—— 那句**已核不成立**（本版 plan 的 `params` 里没有这句），代价实测出来了：**转过 90° 的行假报越界**（22×70 的路 rot 90 ⇒ 假报「出界 8.00 m」，而它世界占地 70×22 **完全在界内**）。11 项具名自检**仍不回来**（2026-09-25 删，它们在替人做决定）；**碰撞检测与布局修正已整段删除**（2026-09-27：重叠**不检、不修**）。旧 `checks` 不再读、也不动（参与那版指纹）。仍有效的形状校验：白膜留空 `asset_path` + 写 `shape` + 写明"预估"；资产必须有 `asset_path` + `scale > 0`。

## 〇、全局场景参数定义与坐标系约定

### 1. 全局场景参数定义（全部做成可配置参数，是工具通用化的关键）

- 世界坐标边界：原点、XY 最大范围、单位（统一米制）
- 道路规则：主干道宽度、人行道宽度、道路曲率/走向
- 地块规则：宅基地面宽、进深、建筑退距（房屋离道路/地界的最小距离）
- 间距规则：行道树间距、路灯间距、灌木最小间距

### 2. 坐标系对齐约定

明确：世界坐标 X/Y 为水平面，Z 为高度；轴向与 UE/Blender 世界轴向严格对应，
提前消除左右手坐标系、单位缩放的坑。

### 工程坑点

- 资产模型**原点不统一**（有的在中心、有的在底部），会导致摆放位置整体偏移，
  **必须在元数据层修正**。
- 不提前定单位，Blender 默认米、UE 默认厘米，生成完会**差 100 倍**。

## 第二阶段：路网生成与地块剖分（布局骨架，纯 2D 几何计算）

### 目标

先搭好"道路-地块"的骨架，而不是直接放房子。骨架决定了整个场景的合理性。

### 核心动作

1. **道路几何生成**
   - 输入：道路中心线（直线/带弧度的曲线）、道路宽度、人行道宽度
   - 输出：主干道、人行道的 2D 多边形（闭合矩形/带状多边形）
   - 附带生成：道路端点、路口位置，标记为"禁止放置区"
2. **宅基地地块剖分**
   沿道路两侧，按设定的地块面宽，垂直于道路方向切割出一块块矩形宅基地。
   - 每块地块自带 2D 包围盒、编号、临路朝向
   - 自动预留：房前草坪区、房屋建筑区
3. **公共区域划分**
   人行道外侧、地块之间的剩余区域，标记为绿化区，用于放置行道树、灌木。

### 技术细节

- **带弧度的道路**：用折线逼近曲线，每段折线对应一排地块，
  保证房屋正面垂直于所在路段的道路方向。
- **路口自动避让**：路口一定范围内不划地块、不种树，符合真实规划逻辑。

### 用户 2026-09-23 的补充规格（原文；与上面「目标 / 核心动作」口径冲突时，**以这版为准**）

> 第二阶段：生成平面布局规划。
>
> 1. 基于参考图的路网走向和地块密度，计算并输出道路网络、宅基地地块的结构化几何数据，保存为 JSON 文件，所有坐标使用米制世界坐标。
> 2. 数据必须包含：道路多边形、地块包围盒、地块朝向、禁止放置区域。
> 3. 只生成一张给用户看的图，让用户确认；此图只做展示，后续计算不得参考该图。
> 4. 全程基于几何计算，不进行图像识别推理。
>
> 这样既保留了可视化校验，又没偏离纯几何驱动的路线。


## 第三阶段：资产初始布局生成（按规则填地块，输出初始位姿）

### 目标

把资产库中的模型，按规则"放进"地块和公共区域，生成所有物体的初始世界位姿。

### 核心动作

1. **建筑层放置**
   - 遍历每块宅基地，从建筑资产库中匹配尺寸合适的户型
   - 强制规则：房屋包围盒完全在建筑区内，不超退距；正面朝向道路
   - 随机化：正负 5° 以内的随机旋转、左右微小偏移，避免完全整齐划一
2. **行道树与路灯放置**
   - 沿人行道边线，按设定间距做等距采样，生成树木坐标
   - 路灯沿道路一侧放置，与树木错开位置，路口加密
3. **灌木与细节填充**
   - 在房前草坪区、绿化区，按密度随机投放灌木
   - 同样遵守最小间距规则，不堆叠、不穿模
4. **输出初始布局表**
   每个物体包含：唯一 ID、资产名称、世界坐标 (X,Y,Z)、旋转角、分类标签、初始 AABB。

### 设计原则：语义规则 + 几何规则双约束

- 语义：房子要朝路、树要种在路边
- 几何：包围盒不能越界、不能重叠

## 第四阶段：碰撞检测与布局修正（核心竞争力，闭环校验）

### 目标

消除所有物体穿插，输出"干净"的布局，这是 VLM 看图方案最做不好的一步。

### 核心动作

1. **分层碰撞检测**
   - 粗检：按网格划分空间，只检测同一格子内的物体，减少计算量
   - 细检：2D AABB 相交检测（只做 XY 平面，符合顶视图平面布局定位）
2. **碰撞修正策略（按优先级）**
   - 低优先级物体（灌木、小树）碰撞：直接平移避让，或删除
   - 高优先级物体（房屋）碰撞：更换小一号户型，或微调地块边界
   - 物体与道路/地块边界碰撞：强制向内平移
3. **迭代收敛**
   循环执行"检测→修正"，直到碰撞数为 0，或达到最大迭代次数。
   - 记录修正次数、剩余碰撞数，作为布局质量指标。

### 工程化要点

- **必须设置最大迭代次数**，防止极端情况死循环。
- 保留碰撞日志，后面可以作为"几何方案 vs VLM 方案"的对比数据。

## 第五阶段：布局数据结构化序列化（MCP 交互的中间语言）

### 目标

生成标准、可复用的布局数据文件，作为 MCP 传给 UE/Blender 的**唯一指令**，
实现"数据和执行分离"。

### 数据结构设计（分层，便于增量修改）

### 输出格式

- 主文件：JSON（通用，易读，MCP 传输方便）
- 附带：碰撞校验报告、布局统计（建筑数量、绿化率、密度）

### 关键价值

后续修改场景，只需要修改 JSON 里对应 ID 的参数，
**不用全部重建，支持增量更新**。

## 第六阶段：DCC 端 MCP 执行与场景实例化

### 目标

把 JSON 布局数据，通过 MCP 变成 UE/Blender 里的真实 3D 场景。

### 核心动作

1. **资产预加载**
   MCP 调用 DCC 接口，批量导入/加载布局中用到的所有资产，提前放到场景资产库。
2. **批量实例化**
   按层遍历布局 JSON，在对应世界坐标生成物体：
   - 先放道路、地面面片
   - 再放建筑、路灯
   - 最后放植被、细节
3. **自动适配层处理**
   - 单位转换、轴向修正（比如 Blender 和 UE 的轴向差异）
   - 材质自动分配：道路材质、草坪材质、房屋外墙材质
4. **静态碰撞体生成（可选）**
   给建筑生成碰撞体，为后续游戏运行时用。

### 优化点

- 相同资产用**实例化（Instancing）**，比如树木、灌木，大幅降低渲染开销。
- **增量更新**：后续修改布局，只传变更的 ID 和新位姿，DCC 端只更新对应物体，
  不用重建全场景。

## 第七阶段：环境灯光与预览相机（参数化，非手工打光）

### 目标

匹配参考图的黄昏效果，同样做成参数化，不用手动调灯。

### 核心动作

1. **环境参数化**
   输入"时间/氛围"参数，自动配置：
   - 天空颜色、天光强度
   - 房屋室内灯光开关、色温（暖黄色）
   - 路灯亮度、照射范围
2. **预览相机生成**
   - 沿人行道生成漫游路径，固定相机高度、FOV
   - 自动计算视野可见范围，做可见性剔除，提升预览速度
   - 输出关键帧预览图，或直接渲染序列帧
   - 相机依然基于**世界坐标**计算，**不靠图像识别判断构图**

---

## 第八阶段：评估与闭环迭代（智能体核心能力）

### 目标

生成完不是终点，支持自动评估 + 人工指令修改，形成闭环。

### 核心动作

1. **自动量化评估**
   输出布局质量指标：
   - 碰撞错误数（0 为合格）
   - 建筑密度、绿化率
   - 资产复用率、空间利用率
2. **指令化修改**
   支持自然语言指令，比如"把左边第三栋房子换成两层的""树木再密一点"：
   - 语义解析 → 定位对应 ID → 修改布局 JSON → 重新碰撞校验 → DCC 增量更新
3. **多轮迭代**
   循环"评估→修改→生成"，直到满足需求。

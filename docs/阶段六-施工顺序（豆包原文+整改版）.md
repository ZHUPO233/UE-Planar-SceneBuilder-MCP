## 一、豆包原文（逐字，未改一字）

分步顺序（UE5标准地编流程，适配你的MCP自动执行）

① 天空系统（最先做）

先定天空氛围：晴天/黄昏/阴天。
UE5.8推荐用 Sky Atmosphere + SkySphere（或者新的Lumen天空）
作用：决定整个场景的基础环境底色、天光颜色，所有物体的漫反射环境光全部来自天空。

为什么第一步：后面打太阳光，必须和天空的色调、太阳位置匹配，不然画面割裂。

② 大气与体积雾

打开体积雾，和天空大气绑定。
控制空气通透度、远处朦胧感、雾的高度。小镇远景层次感全靠这个。

注意：体积雾会影响太阳光的光束（丁达尔），必须在太阳光之前配置。

③ 主定向光（太阳光）

设置太阳角度、强度、色温。

- 正午：强光，硬阴影

- 黄昏：低角度长阴影，暖色调

主光源产生场景最核心的阴影，物体已经摆好，阴影直接投射在地面、建筑上。

④ 环境补光 + 局部光源

1. 天光（SkyLight）：拾取天空，给物体暗部补光，防止死黑

2. 室内点光源/面光源：房子内部灯光、路灯。

路灯属于小型点光源，放在你之前MCP摆好的路灯Actor位置，直接读取JSON坐标批量生成。

⑤ 天气粒子（雨/雪，就是你刚才找的这套）

Niagara粒子系统，放在整个小镇上空。

- 雨：雨滴GPU粒子 + 地面水花碰撞

- 雪：落雪循环粒子

放在光源后面：粒子会被光照照亮，雨/雪才能被看见；如果先放粒子再打光，容易出现粒子不受光照的bug。

⑥ 预览相机（最后一步）

创建顶视图/漫游相机，固定机位，输出预览画面。

## 二、整改后的执行顺序（原文块**搬过来**，一字未改；批注单独成段）

### 第 0 步（我方新增，非豆包原文）
**找 / 建载体**：按**类**找 Actor；因素表里标了 `spawn: true` 的、关卡里没有就建一个（实测：后处理卷关卡里 0 个 → 必建；局部体积雾同理）。
> 判据与实现见 `main.py` 的 `ENV_FACTORS_DEFAULT` 与 `_env_locate()` / `_env_spawn_actor()`。

### 第 1 步 ← 豆包的 **③**

③ 主定向光（太阳光）

设置太阳角度、强度、色温。

- 正午：强光，硬阴影

- 黄昏：低角度长阴影，暖色调

主光源产生场景最核心的阴影，物体已经摆好，阴影直接投射在地面、建筑上。

**【整改批注 · 为什么把它提到最前】**
豆包把它排在 ① 天空 **之后**，我们要对调。依据是**实测**：本工程太阳组件上
`bAtmosphereSunLight = true`、`atmosphereSunLightIndex = 0`
（2026-09-29 用 `get_properties` 读到的原始值）—— **太阳就是天空大气的光源**，
天空的颜色/亮度**由太阳的位置与强度决定**。先定天空、后定太阳 = **先定的那次白定**。

### 第 2 步 ← 豆包的 **①**

① 天空系统（最先做）

先定天空氛围：晴天/黄昏/阴天。
UE5.8推荐用 Sky Atmosphere + SkySphere（或者新的Lumen天空）
作用：决定整个场景的基础环境底色、天光颜色，所有物体的漫反射环境光全部来自天空。

为什么第一步：后面打太阳光，必须和天空的色调、太阳位置匹配，不然画面割裂。

**【整改批注】**
- 位置：从"第 1 步"挪到"**太阳之后**"（理由见上一步）。
- 概念：`Sky Atmosphere` 是**天空本体**；`SkyLight` 是**拾取天空的环境补光**，两个不同的 Actor。
  豆包在本条里把天光并进"天空系统"，又在 ④ 重提 —— 我们**拆成两个因素**：
  `sky_atmosphere`（这一步）与 `sky_light`（下一步）。
- 是否加 `SkySphere`：**美术选择**。实测本工程关卡只有 `SkyAtmosphere_0` + `SkyLight_0`
  （`search_subclasses(/Script/Engine.Actor, "Sky")` 另回 `BP_Sky_Sphere_C` 可选）。
  **当前没有加**，天空由 SkyAtmosphere 提供。

### 第 3 步 ← 豆包的 **④ 之"1. 天光"**

1. 天光（SkyLight）：拾取天空，给物体暗部补光，防止死黑

**【整改批注】**
- 从 ④ 里**拆出来单独成步**：它依赖上一步的天空（"拾取天空"是自己写的），**天空之后、其它之前**最自然。
- 实测：本工程 `SkyLight_0` 的 `bRealTimeCapture = true`、`sourceType = SLS_CapturedScene`
  → 它**实时拾取**天空，所以必须在天空配好之后再配它。

### 第 4 步 ← 豆包的 **②**

② 大气与体积雾

打开体积雾，和天空大气绑定。
控制空气通透度、远处朦胧感、雾的高度。小镇远景层次感全靠这个。

注意：体积雾会影响太阳光的光束（丁达尔），必须在太阳光之前配置。

**【整改批注 · 这条"必须在太阳光之前"我们不改原文，但不采纳为执行约束】**
- 理由：我们是**参数写入**（等价于"所有属性都设好、然后才渲染"）。UE 的雾/大气/太阳
  都是**每帧实时计算**的，**写入先后不影响最终画面**。豆包那条约束来自**烘焙 / 静态光照**
  的心智模型（光照贴图、编译期）。
- **真正常见的顺序约束只有一条**：**会触发 shader 重编译的东西要排最后**（见第 8 步），
  这条我们**实测过**（改 `MaterialInstanceTools` 的 **static switch** 会触发重编译，官方文档也明说）。
- 体积雾本身在本工程是**高度雾组件上的开关**：实测 `bEnableVolumetricFog`
  （`ExponentialHeightFog` 的 `HeightFogComponent0`）。
- 【2026-09-29 接手会话补】**`local_fog`（局部体积雾）归在「这一族」**：它是后来从配置
  （`config/environments.json` 的 `factors` 段）加进来的因素，豆包原文 / 整改版都**没有给它单列成步**。
  按归类把它放进雾族 —— 执行顺序里紧跟 `fog`、在 `cloud` 之前（`main.py` 的 `ENV_FACTOR_ORDER`）。
  ⚠ 这是**判断、不是实测**：调换它对最终画面没有影响（都是逐帧生效的属性写入 + 新建一个 Actor）。

### 第 5 步（我方新增，豆包原文没有这一条）
**体积云**：组件级参数（`layerBottomAltitude` / `layerHeight` / `tracingMaxDistance`）
+ **材质级**参数（云量 `Cloud_GlobalCoverage` / 云密度 `Cloud_GlobalDensity` / 云色 `Cloud_AlbedoColor`）。
> 实测：云量/云密度在**材质**上（引擎 MI `m_SimpleVolumetricCloud_Inst`）。做法是
> `create` 一个**我们自己的 MI**（父级=引擎那个）→ 把云组件的 `material` 指过去 → 再调参数。
> 这样**只改这张图**，不动引擎资产。详见 `docs/阶段六-可用环境参数.md`。

路灯属于小型点光源，放在你之前MCP摆好的路灯Actor位置，直接读取JSON坐标批量生成。

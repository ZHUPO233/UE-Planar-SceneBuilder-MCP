## 甲 · 可用环境参数

### 三、后处理（`PostProcessVolume`）

- 它的参数在一个**结构体** `settings` 里（**实测 463 个字段**），命名规则是成对的：
  **覆盖开关 `bOverride_<驼峰名>` + 值字段 `<驼峰名>`**（例：`bOverride_BloomIntensity` / `bloomIntensity`）。
- 预设里**已用** 9 组：`autoExposureMinBrightness` / `autoExposureMaxBrightness` / `autoExposureBias` /
  `bloomIntensity` / `bloomThreshold` / `whiteTemp` / `vignetteIntensity` / `filmGrainIntensity` /
  `sceneFringeIntensity` / `toneCurveAmount`（+ 各自 `bOverride_*`）。
- 其余大可用（实测存在）：`colorSaturation` `colorContrast` `colorGamma` `colorGain` `colorOffset`
  （**注意：这几个是 `{x,y,z,w}` 四分量**，不是 `{r,g,b,a}`）`colorGradingIntensity` `colorGradingLUT`
  `sceneColorTint` `chromaticAberrationStartOffset` `motionBlurAmount` `ambientOcclusionIntensity`
  `lensFlareIntensity` `sharpen` `depthOfField*` `dynamicGlobalIlluminationMethod` `reflectionMethod`
  `lumen*` `rayTracing*` `pathTracing*` `filmSlope` `filmToe` `filmShoulder` `blueCorrection` `expandGamut` …
- ⚠ **未知键会被静默写坏**，所以口径是「**先读现值 → 合并 → 整份写**」；
  要查全量：`ObjectTools.list_properties(instance=那个卷)`（`settings` 那段就是全部字段）。

### 五、两个**还没进表**的扩展方向（要改代码 / 要拍板）

#### 1) `LocalFogVolume`（UE5 局部体积雾）—— 参数表已经捞到了
`list_properties(instance=/Script/Engine.LocalFogVolumeComponent)`（**对类对象也能读**，实测回 34 个属性）：

```
fogAlbedo  fogEmissive  fogStartDistance  heightFogExtinction  heightFogFalloff
heightFogOffset  radialFogExtinction   (+ bAbsoluteScale / relativeScale3D 这类通用项)
```

**要支持它，现在有两步**：① 往因素表里加一行（key / 中文名 / 类路径 `/Script/Engine.LocalFogVolume`）；
② 加组件名提示 `LocalFogVolumeComponent`。**但现在这两张表在代码里**（`main.py` 的 `ENV_FACTORS` /
`ENV_COMPONENT_HINT`）→ 加它得**改代码**。建议把它们也搬进 `config/environments.json`（见第六节）。

#### 2) 自己的材质（云 / 体积雾的"盖多少"）—— 工具齐了，但涉及新建资产
实测 `MaterialInstanceTools` 有：`list_parameters` / `get_/set_scalar_parameter` /
`get_/set_vector_parameter` / `set_texture_parameter` / `set_static_switch_parameter` / `create`
（新建材质实例）/ `set_parent`。

引擎那朵云的材质**实测有这些参数**（`list_parameters` 原始返回，29 个）：

```

Vector : Cloud_AlbedoColor  Layout_WindControls  Layout_CloudType  Layout_CloudPerTypeScale
         Layout_CloudTypeMask  Layout_GlobalTexturePlacement  Multiscatter_Controls  Phase_Controls
         Noise_Bias  Noise_Strength  Noise1/2/3_Coordinates  Noise3_MultChannel
         Storm_AlbedoColor  Storm_Lightning* …
Texture: Layout_CloudGlobalPattern  Layout_CloudHeightProfile  Layout_GlobalCloudMask  Noise_Texture3D

```

⚠ **云量 / 云密度就在 `Cloud_GlobalCoverage` / `Cloud_GlobalDensity`** —— 所以要改它有两条路：

| 路线 | 做法 | 代价 |
|---|---|---|
| **改引擎 MI（不推荐）** | 直接 `set_scalar_parameter` 改 `/Engine/.../m_SimpleVolumetricCloud_Inst` | **动引擎资产**：所有用它的关卡一起变（本项目纪律不允许） |
| **建自己的 MI（干净）** | `create` 一个以它为父级的新 MI → 把云组件的 **`material`** 指向它 → 再 `set_scalar_parameter("Cloud_GlobalCoverage", …)` | **新建 UE 资产**（要存盘才持久）—— 需要用户拍板放开这条口子 |

### 六、当前限制（如实）

1. **同类多个只改第一个**：`_env_locate` 按类找、命中多个时取第一个，并**在 warnings 里点名**
   （例：「关卡里有 2 个 ExponentialHeightFog —— 这次改的是第一个」）。
   → 想指定"改哪一个"，需要给 `setup_environment` 加一个**按 label / 引用选 Actor** 的参数。
2. **自定义蓝图类**（`BP_VolumetricFog_C` 这种）：因素表里没有 → 找不到就跳过。
   要支持得往表里加类路径（最好连表一起搬到配置里）。
3. **新增一个"因素"（新的类）要改代码**：属性可以全写在配置里，但"有哪些因素 / 每个的类路径与组件名"
   这两张表在 `main.py` 里。**这一条与材质表那次是同一个教训** —— 内容应该归配置。
4. 云量 / 云密度：见第五节的"建自己的 MI"那条路。

### 七、怎么自己把**任意类**的参数表捞出来（两步，实测可行）

```
① 找类：  ObjectTools.search_subclasses(base_class = /Script/Engine.Actor, class_name = "Fog")
          → 回 [ExponentialHeightFog, LocalFogVolume, AtmosphericFog]
② 读参数：ObjectTools.list_properties(instance = {"refPath": "/Script/Engine.LocalFogVolumeComponent"})
          → 对**类对象**也能读（实测回 34 个属性）—— **不用先把它摆进关卡**
③ 若是材质：MaterialInstanceTools.list_parameters(material = <材质/MI 引用>) → 名字 + 类型
```

⚠ 读出来的是**参数名与类型**；**能不能写进去、写完读回是不是它**，仍要真跑一次才知道
（本项目踩过"以为能写、其实结构体被整体替换"这种坑，见 `AGENTS.md` 阶段六那条）。

## 乙 · 施工顺序

> **本阶段 = 环境搭建**：使用物是**环境参数**（不是图）；施工顺序**到第 8 步为止**；验收 = **在 UE 里自己看**。
> ⚠ 外部流程原文、逐条理由与当时的踩坑流水**不在本文件**（归档在 `docs/archive/阶段六-施工顺序-原稿-2026-09-30.md`）——
> 这里只留**执行顺序、每步要写什么、判据、依据等级**。

### 一、顺序总览

**载体的找 / 建**（全部在写之前）→ `sun` → `sky_atmosphere` → `sky_light` → `fog` → `local_fog` → `cloud` → `post_process`

⚠ 这道顺序**由代码保证**（`main.py` 的 `ENV_FACTOR_ORDER`），**不是**靠 `config/environments.json` 的键序
—— 配置文件是人天天改的表，靠它定顺序 = 谁挪一行就乱，而且**工具不拦也不报**。
⚠ 不在表里的自定义因素**排到最后**并在报文里**点名**（与阶段三"不在五层表里 → 未分层"同一条纪律）。

### 二、逐步要做什么

#### 第 0 步 · 找 / 建载体
按**类**找 Actor；因素表里标了 `spawn: true`、关卡里又没有的，就建一个（后处理卷：关卡里 0 个 → 必建；局部体积雾同理）。
> 实现见 `main.py` 的 `ENV_FACTORS_DEFAULT` / `_env_locate()` / `_env_spawn_actor()`。

#### 第 1 步 · 太阳（`sun`）
设置太阳角度 / 强度 / 色温。正午 = 强光 + 硬阴影；黄昏 = 低角度长阴影 + 暖色调。
⚠ **必须排在天空之前**：实测太阳组件上 `bAtmosphereSunLight = true` —— **天空的颜色与亮度由太阳决定**，
先定天空、后定太阳 = **先定的那次白定**。

#### 第 2 步 · 天空大气（`sky_atmosphere`）
先定天空氛围（晴天 / 黄昏 / 阴天）—— 它决定整个场景的底色与漫反射环境光。
⚠ `Sky Atmosphere` 是**天空本体**，`SkyLight` 是**拾取天空的环境补光**，是两个不同的 Actor → 拆成两步（本步 + 下一步）。
⚠ 要不要再加 `SkySphere` 是**美术选择**：实测本工程只有 `SkyAtmosphere_0` + `SkyLight_0`（当前没加，天空由 SkyAtmosphere 提供）。

#### 第 3 步 · 天光（`sky_light`）
拾取天空、给暗部补光、防死黑。
⚠ 必须在**天空配好之后**：实测 `SkyLight_0` 的 `bRealTimeCapture = true` / `sourceType = SLS_CapturedScene`
—— 它**实时拾取**天空，天空没配好它拾到的就是错的。

#### 第 4 步 · 高度雾 / 体积雾（`fog`）
打开体积雾，控制空气通透度与远景层次。
- 体积雾在本工程是**高度雾组件上的开关**：`bEnableVolumetricFog`（`HeightFogComponent0`）。
- ⚠ **雾不必须排在太阳之前**：我们是**参数写入**，雾 / 大气 / 太阳都是**每帧实时计算**的，
  写入先后不影响最终画面（"雾必须在太阳之前"来自**烘焙 / 静态光照**的心智模型）。
  **唯一实测过的顺序约束**是"**会触发 shader 重编译的写入排最后**"（见第 8 步）。

#### 第 5 步 · 局部体积雾（`local_fog`）
按**归类**紧跟 `fog`、在 `cloud` 之前（它是后来从配置加进来的因素）。
⚠ 这是**判断、不是实测**：调换它对最终画面没有影响（都是逐帧生效的属性写入 + 新建一个 Actor）。

#### 第 6 步 · 体积云（`cloud`）
组件级参数（`layerBottomAltitude` / `layerHeight` / `tracingMaxDistance`）
+ 材质级参数（云量 `Cloud_GlobalCoverage` / 云密度 `Cloud_GlobalDensity` / 云色 `Cloud_AlbedoColor`）。
> 实测：云量 / 云密度在**材质**上（引擎 MI `m_SimpleVolumetricCloud_Inst`）。做法是 `create` 一份
> **我们自己的 MI**（父级 = 引擎那个）→ 把云组件的 `material` 指过去 → 再调参数 —— 这样**只改这张图**、不动引擎资产。
> 详见本文件「甲 · 可用环境参数」。

#### 第 7 步 · 后处理（`post_process`）
`bUnbound` + `settings` 里那一批（曝光 / Bloom / 白平衡 / 暗角 / 颗粒 / 色差 / 色调曲线）。
⚠ `settings` 是**结构体，必须整份写**（只写一个键会把其余键打坏）；报文与台账里**只记改动的那几条**。

#### 第 8 步 · 会触发重编译的写入排最后
典型是材质实例的 **static switch**（`set_static_switch_parameter`）—— 实测 + 官方文档：改它会触发 **shader 重编译**。
⚠ **当前未实现**：材质参数是**就地**写在那个因素后面的；当前配置里没有任何布尔参数 → **零副作用**，
真用到时那一行会如实报"它没排最后"。

#### 第 9 步 · 出图 —— **不属本阶段**（归阶段七）
`capture_preview()` 的代码**保留**（已实测：不动用户的视口相机、两档标注），**归阶段七**用。
本阶段**不出图**，验收 = **在 UE 里自己看**（不满意 → 改 `config/environments.json` → 重跑，不用改代码、不用重启）。

#### 第 10 步 · 天气粒子（雨 / 雪）—— **不做**
相关编排代码**已删**（它**从未真跑验证过**，留着会让人误以为这套有 Niagara 能力）。
⚠ 表述纪律：官方那侧的能力**还在** —— 说法是"**这一版没把它编排进来**"，**不是"我们没有这个能力"**。
⚠ 该条的原文块与摸底实况（含作者本机工程的资产清单）**属作者本机工程，这份使用包里已删**。

## 阶段六的口径（2026-09-29 加：环境搭建）

> ⚠ **本阶段叫「环境搭建」（2026-09-29 用户最终定名）** —— 原名「环境搭建与**相机预览**」是

- **范围**：用户原话「阶段6改一下，叫环境搭建和相机预，不只有灯光，其他环境因素全部要做」。

  但**已划给阶段七**（见下），**不算本阶段的使用物**。
  时段预设表在 **`config/environments.json`**（**每次调用都重读**：改它不用改代码、不用重启 —— 与材质表同一条纪律）。
- **走的是「复用并改关卡原生那 5 个环境 Actor」**（用户 2026-09-29 在两条路里选的 a）——
  所以**动手前先记现值**，台账 `views/environment_state_v1.json` 是回滚依据，
  `setup_environment(restore=true)` 照它写回。
  ⚠ **同一因素只记第一次**：覆盖式记录会让回滚退不回"我们动手前"那一版。
  ⚠ **台账齐全 ≠ 回滚能用**（2026-09-29 实测踩到，**别再把这两件事混着说**）：那条路**第一次被真走**
  （零副作用的演练 `restore=true, dry_run=true`）就失败 —— 两处洞都已改（后**自查补了第三处**），
  **三条靶子均已实测通过**（证据见 `docs/阶段六-环境搭建.md` 的「乙 · 四」）：
  ① 台账里的 **Actor 引用会过期**（存盘 / 重开关卡之后重建会换名，实测引用指向不存在的对象，
     而旧代码**先信后不验** → 既不回退按类找、也不走 `spawn`，直接失败）→ 现在**先 `get_label` 验活**；
  ② **我们自己建的** Actor（`UEMCP_env/` 下的后处理卷 / 局部体积雾）回滚时是**删掉**，
     不是"写回引擎默认值"（那是我们建它时读到的默认值，写回去只会留个空壳；它动手前**不存在**）。
     认"哪些是我们建的"**靠分组、不靠名字**（官方给的名字对 Actor 名不生效）。
  ⚠ **`restore` 是"整份回滚"，不是"撤销上一步"**（2026-10-07 补记 · 用户实测撞过）：
    台账里**同一因素只记第一次**（见上一条）⇒ `restore=true` 只能把**所有**因素一起退回
    "我们第一次动手之前"那一版。**"把上一步改的那个因素退回去、别的别动"做不到** ——
    实测：把雾调朦胧之后想只撤回那一步，`restore=true` 把 7 个因素全退了（用户原话「我去撤回太阴了」
    →「我只是让你撤回刚刚的操作」）。
    ⚠ 修法（**未做**）：要支持"单步撤销"，得写回**已知的目标值**（按因素逐个写），
      而不是拿台账那一份整体覆盖 —— 那是一条**新通道**，不是把 `restore` 改小。
    ⚠ 另一条如实记着：`restore` 报文里那个 `before` 值**来自台账**（我们记的现值），
      **不是从关卡现场读回来的** —— 所以它证明不了"关卡现在真的长那样"。

     "未设置=保持不变"，**实测不是**）。所以口径是"**先读现值 → 合并 → 整份写**"
     （`_env_write_value` / `_env_apply_factor`），**别改回局部写**。
- **云量 / 云密度：不能"直接改"，但能改**（**2026-09-29 更正 + 用户授权做** —— 此前这条写的是
  "改不了"，那是**作废口径**）：它们挂在**引擎自带**的体积云材质实例上
  （`/Engine/EngineSky/VolumetricClouds/m_SimpleVolumetricCloud_Inst`）—— 直接改它就是改引擎资产

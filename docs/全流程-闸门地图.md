## 二、逐道闸：判据与出路

### G1 · 开场前置 `_session_prereq_guard()`（`main.py:5717`）
**判据**：本次会话没调过 `official_status()` 与 `get_asset_list()`。
**为什么**：讲流程之前先查状态 —— 不查就会拿记忆当事实（2026-09-23 反例：资产清单早已签字，却拿新拼的 15 元素清单去请用户确认）。
**出路**：调那两个只读工具，各一次。

### G2 · 搭哪张图 `_build_target_guard()`（`main.py:1881`）
**判据**：`views/build_target_v1.json` 里那份**用户答复**必须存在，且与**当前关卡**对得上。
**为什么**：客户原话「别动用户的 UE」。官方**没有「新建关卡」的工具** —— 所以「开新图」得用户自己在 UE 里建。
**出路**：`check_build_target()`（先只读地问 → 停下等用户打字 → 带他的原话再调一次记下来）。
⚠ **演练与 `adopt=true` 不拦**（它们不碰关卡）。

### G3 · 阶段二闸门（`planning.gate_check()`）
**判据**：`confirmed` + 几何指纹。**规划一改（坐标 / 占地 / 参数任何一处），指纹就对不上，上一次确认自动作废。**
**出路**：重画图 → 用户看图点头 → `confirm_plan()`。

### G4 · 回读闸 `_readback_guard()`（`main.py:5664`）
**判据**：写盘之后必须调过 `get_plan()`（那一次调用会被记成「这一版你回读过了」）。
**为什么**：不调它，就等于**写盘的人自己都没看写成了什么**。
⚠ 台账读不动 → **放行**（基础设施故障不拦人）。

### G5 · 改动窗口 `_change_request_guard()`（`main.py:5741`）
**三条判据同时成立才拦**（源码原话）：
1. 这一版与盘上那版**指纹不同**（**原样重发 / 一模一样地重发不拦**）；
2. 之前**确认过至少一版**（第一次排表不受影响）；
3. 台账的**改动窗口是关着的**（由 `request_plan_change()` 开、由 `confirm_plan()` 关）。
**为什么**：客户 agent 自评原话「用户提改动要调 `request_plan_change` —— **一次都没调过**，你每次说要改，我直接 patch，没走变更台账」。
**出路**：用户提的 → `by="用户"` + 他的原话；自查要修 → `by="agent 自查"`。

### G6 · 整批校验 `_precheck_build()`（`main.py:2581`）
**一条不过 → 一个 Actor 都不落**（与 `confirm_assets` 拒收时「一个字节都不写」同源）。
校验项：阶段二闸门 + 几何指纹 + 验收状态 + 用户原话；资产行路径逐个 `exists()`；白膜行不许带路径、必须有图元与三维尺寸；**行数 == plan 的 `assets + whiteboxes`**。
**实测**：2026-09-30 演练，90 行全过（`planned: 90`）。

### G7 · 人工痕迹 `_live_vs_ledger()`（`main.py:2039`，**2026-09-30 实测更正**）
**判据**：动手前读**关卡现状**与台账比 —— 位置 / 朝向 / 缩放 / 白膜厚薄；对不上的算「人工改过」。
⚠ **位置容差 0.5 cm**（不是读回对账那 0.05）—— 这里判的是「**人手动挪过没有**」。

**⚠ 更正：它**不是**「全表默认拒收」。真正的机制（源码 `main.py:3355-3423`，2026-09-30 实跑验证）**：

| 情形 | 扫描范围 | 会不会拒收 |
|---|---|---|
| `dry_run=true`（演练） | **全表** | ❌ 不拒收（只列在 warnings 里，`refused` 仍是 `false`） |
| `accept_user_edits=true` | **全表** | ❌ 不拒收（人工改过的行**被当成改动重摆**，按 plan 覆盖） |
| `mode="full"` | **全表** | ✅ 台账能认但被改过的 + **台账解释不了的活 Actor**，两者都算痕迹 |
| **纯增量真跑（默认那条）** | **只扫「这次会被删 / 重摆的那些行」** | ✅ **只有落在这些行里的人工痕迹才拒收** |

拒收条件（源码原话）：`if traces and not accept_user_edits and not dry_run: raise`。
**纯增量真跑时，改动集之外的人工痕迹是「静默保留」** —— 保住你手改的东西，但**不报告**。

**实测证据（2026-09-30）**：
- `evaluate_layout()` 报「世界地基」与台账差 10 cm（`[0,0,5]` → `[0,0,-5]`，用户手挪的）；
- 紧接着真跑 `execute_build()`（不带参数）：**没有拒收**、`人工改过（现状与台账不符）: {}`、`没动 7`、
  `removed 0 / placed 0`，台账里那一行**仍记 `[0,0,5]`**。
- 原因：那一版 plan 的 7 行与台账逐行相同 → **改动集为空** → `scan_rows = []` → 不扫 → `traces = []`。
  （`evaluate_layout` 是全表扫的，所以**两个工具会给出看似矛盾的结论** —— 不是 bug，是**扫描范围不同**。）

**出路**（要在增量里真正触发拒收）：**让那一行进入改动集** —— 即 plan 里那一行这次要变（或要被删）。
· 保住用户的改动（推荐）：`request_plan_change` → `generate_plan(patch=…)` 把它写回 plan → **重画图** → 用户确认 → 增量落；
· 按 plan 覆盖：显式传 `accept_user_edits=true`（**会把你手改的覆盖掉**）。

**✅ 实测证据（2026-09-30 · 这条闸的拒收路径第一次真跑）** —— 实验设计来自 ChatGPT 的评估
（「手动修改 house #1 ＋ Patch 恰好也要修改 house #1 → 预期 REJECT」，证明 *User Edit Protection 在冲突对象上有效*）：
1. 用户在 UE 里手拖 `住宅 #1`：实际 `(0, -2090, 15)`，台账记 `(0, -4800, 15)`（差 27.1 m）；
2. 那一轮的 patch 也改 `住宅 #1`（挪回 `[-20,-18]`）→ 它进了 `changed` → 进扫描范围；
3. `execute_build()` 真跑 → **REJECT**，原文：
   `拒绝搭建：UEMCP/ 下有 1 处人工痕迹会被这次操作删掉 —— 一个 Actor 都没动：· 「住宅 #1（house1）」位置 [0.0, -4800.0, 15.0] → 现在 [0.0, -2090.0, 15.0]`
   （并给出两条出路：写回 plan / `accept_user_edits=true` 覆盖）
4. **独立复核"没动"**：房子的实际变换仍是 `(0,-2090,15)`（用户手挪的没丢）；
   台账文件 `at` 仍是上一次落盘时刻（`05:25:43`）→ **拒收没写台账**。

### G8 · 全量保护 `_resolve_build_mode()`（`main.py:2660`）
**判据**：`mode="full"` 真跑时，`force_full` 与 `accept_user_edits` **两个都要给**。
**为什么**：全量会把 `UEMCP/` 下的 Actor **全删了重摆** —— 客户原话「用户手动改的东西不该删」。
**出路**：改几行就走增量；真要全量就两个都传。

### G9 · 越界体检（`BOUNDS_TIERS`）
**三级判据**：**硬·实体**（`house` / `tree` / `shrub`，**以及表里没有的一切 element_key**）四角必须都在界内；**软·铺装**（`road` / `sidewalk` / `path` / `grass`）允许贴边、不许超出；**豁免·边界元素**（`ground`）自己就是世界边界。
⚠ **只报红、不拦**（2026-09-27 用户拍板；2026-09-30 用户再次确认保持）。
**实测**：today 报 **15 处**（6 处硬实体各 0.20 m、9 处软铺装最多 1.61 m）。
判的是**中心**与**占地四角**（`footprint_m` 当世界轴对齐尺寸用，**不叠 `rot_deg`**）。

### G10 · 材质路径 `_surface_materials()`（`main.py:250`）
**判据**：`config/surface_materials.json` 里的路径**逐个** `exists()` —— 不过就**拒收**（那一次一个元素都不贴）。
⚠ 配置缺了 / 坏了 → 退回代码里的 `SURFACE_MATERIAL_DEFAULT`（**故意是空的**）→ **一个都不贴**并把原因写进 `warnings`，**不假装"贴了"**。

### G11 · 环境回滚 `_env_ledger()`（`main.py:7714`）
**判据**：`views/environment_state_v1.json`。没有台账 = 没有可回滚的东西。
⚠ **同一因素只记第一次**（覆盖式记录会让回滚退不回原地）。
⚠ 台账里记的 **Actor 引用会先验活**；**我们自己建的**（`UEMCP_env/` 下）回滚时是**删掉**、不是写回引擎默认值。
⚠ **状态**：三处洞 2026-09-29 已修，**修法尚未复验**（`setup_environment(restore=true, dry_run=true)` 是零副作用的验法）。

### G12 · 资产清单（阶段一）`confirm_assets`
**判据**：路径验证不通过的行**直接拒收**（不是警告）；白膜行四样（`is_placeholder` / `placeholder_shape` / `size_cm` / `size_source`）**缺一不可**，填错**当场拒收**。
**出路**：要么给对路径，要么登记成白膜占位 —— **没有第三条**（不许跳过，跳过 = 让元素静默消失）。

## 三、⚠ 明确「没有闸门」的地方（别把「没拦」当成「没问题」）

这几处是**故意不设闸**的，写在这里免得下次又被当成 bug 报：

| 地方 | 现状 | 谁定的 |
|---|---|---|
| **越界** | 只报红、不拦 | 用户 2026-09-27 拍板、2026-09-30 复确认 |
| **碰撞 / 重叠** | **不检、不修**（碰撞检测与布局修正**已整段删除**） | 用户 2026-09-27 指令 |
| **读回对账不通过** | **只报不修、没有回滚**（`_verify_rows()` 把差异塞进 `mismatches` 列表） | —— 这是**真实缺口**，不是设计 |
| **`evaluate_layout` 的结论** | **只报数、不判合格不合格、不改任何东西** | 用户 2026-09-30（「阶段二那 11 项自检就是因为替用户做决定被整段删掉的」） |
| **`token_match` 匹配失败** | **没有闸** —— `plan_assets` 对带 `_`/`-` 的资产名给**假阴性**，而它被当成事实往下走 | ⚠ **未修的缺陷**，见第四节 |
| **UE 连不上时的 `evaluate_layout`** | **不报错**，只出 `plan ↔ 台账` 那半 + 一条点名警告 | 用户 2026-09-30（「不许把『没报』当成『没问题』」） |

**两条最要紧的**：
- 「读回对账不通过 → 不回滚」= 写**之前**的闸确实「一个 Actor 都不动」，写**之后**发现不对**没有退路**。别承诺做不到的事。
- 「UE 连不上 → 不报错」= 那一次报告的**完整性是打折的**，必须读 `warnings` 才知道少查了哪一维。

## 四、已知缺陷（**只登记，未修**）

### D1 · `token_match` 认不出带分隔符的资产名（`main.py:780`）
**现象（实测 2026-09-30）**：
```
官方枚举：/Game/<你的工程目录>/mcp_mats/MI_Asphalt     ← 在
          /Game/<你的工程目录>/MI_Cloud_Sunset          ← 也在
plan_assets(["MI_Asphalt"])  →  found: 0, missing: 1     ← 说没有
（路径写成通用形式；原实测路径属作者本机工程）
```
**根因（源码）**：`token_match` 把**文本**切成词，却拿**整个关键词**去比**单个词**。
关键词 `MI_Asphalt` → `kw = "mi_asphalt"`（一个整串）；资产名被切成 `["mi", "asphalt"]`（两个词）。
两个方向都对不上 → **永远匹配不了**。
**影响面**：`token_match` → `candidates_for` → **`plan_assets`** 与 **`get_asset_list` 的 `new_candidates`**。
**不碰**：plan / 几何指纹 / 任何闸门（纯匹配逻辑）。
**为什么一直没暴露**：`elements.json` 的关键词（house / tree / grass / road / sidewalk / path / shrub / window / sky）**全是单词**。
**危害等级**：高 —— 它给的是**假阴性**，而阶段一的规则是「找不到 → 登记白膜占位」，
于是会**把存在的资产做成白膜**，且报告里完全看不出这是误判。
**修法（待授权）**：让关键词走**同一套切词**，再按「连续词序列」匹配。只改 `token_match` 一个函数。

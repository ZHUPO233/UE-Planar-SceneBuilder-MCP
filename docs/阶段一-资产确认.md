# 阶段一 · 资产确认

> 本文件是**唯一保留的规范文档**。`docs/` 下其余 15 个文档已于 2026-09-23 按用户要求全部删除。
> 本文件只记录**用户口述的流程要求**和它的落地映射，不记录进度、不记录我的分析过程。

---

## 一、用户的要求（原文，一字未改）

> 根据上传图片提取所需资产让用户确认，然后寻找资产，找到名字对得上的就是找到了，
> 没找到就禁止寻找疑似的，直接告知用户缺少什么资产，并要求用户把存在但是agent没找到的
> 资产的路径和名字告诉agent，让agent重命名，最后确认资产列表并向用户确认

---

## 二、拆成步骤

| # | 步骤 | 谁做 | 对应工具 |
|---|---|---|---|
| 1 | 从上传的图片里提取所需资产（元素清单） | Agent | （读图，无工具） |
| 2 | **让用户确认**这份元素清单 | 用户 | — |
| 3 | 寻找资产 | Agent | `plan_assets` |
| 4 | **名字对得上 = 找到了** | Agent | `plan_assets`（按资产名 + 按文件夹名，两条路） |
| 5 | 没找到 → **禁止寻找疑似的**，直接告知用户缺什么 | Agent | `plan_assets` |
| 6 | 要求用户把"**存在但 Agent 没找到**"的资产的**路径 + 名字**告诉 Agent | 用户 | — |
| 7 | 让 Agent 重命名 | Agent | `rename_assets`（默认只预览，不真改） |
| 8 | 确认资产列表，**并向用户确认** | Agent → 用户 | `confirm_assets` |

**用户没确认资产列表之前，不许进入阶段二（搭建）。**

---

## 三、硬规则

1. **禁止寻找或猜测"疑似资产"。** 找到就是找到，没找到就是没找到。
2. 没找到时**不许拿别的资产顶替**，也**不许列一堆候选让用户挑**。
3. 缺失的资产，由**用户**给出路径和名字 —— 谁的项目谁认得。
4. 用户确认资产列表前，不许摆放任何东西。

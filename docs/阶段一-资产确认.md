# 阶段一 · 资产确认

**用户要求**：根据上传图片提取所需资产**让用户确认** → 找资产，**名字对得上的就是找到了**，没找到**禁止找疑似的**，直接告知缺什么，并要求用户把【路径 + 名字】给 agent 重命名 → 最后确认资产列表并向用户确认。

**⚠ 开工前先向用户要参考图**：**顶视图**（看平面：摆在哪儿 / 占地多大 → `pos` / `footprint_m`）+ **左右视图**（看高度与立面 → `height_m` / 体量）。三条口径：① **只是建议、不是硬闸**（`source_image` 可留空）；② **只有一张也能做**；③ 缺的那一路只能**目测预估**，清单里必须标「**预估待核实**」（硬规则 ⑥：预估值不许伪装成实测值）。

**流程**：先有那张表 `config/asset_categories.json`（**11 个资产大类** + **2 个场景项**：地图大小 / 地图对应时间）→ 读图把元素**填进表里对应的大类**（有数量的填预估 `count` + `count_source`；场景项必填）→ **让用户确认这张表** → `find_assets` 按资产名 + 文件夹名两路找 → 没资产的元素**登记白膜占位** → `confirm_assets` 逐个 `exists()` + 实测包围盒 → 使用按大类分组的清单请用户确认。

**硬规则**：① 禁止猜"疑似资产"；② 没找到不许拿别的顶替，也不许列一堆候选让用户挑；③ 缺失资产由**用户**给路径与名字；④ 用户确认前**不许摆任何东西**；⑤ 白膜只是"清单登记"，真生成在**阶段三**（`execute_build` 用官方 `PrimitiveTools` 加图元，不建资产、不存盘）；⑥ **预估值不许伪装成实测值** —— `size_source` 必须写明"预估（参考图目测，待核实）"。

⚠ **「世界地基」漏登记会报红（2026-10-12 加 · 只报红、不拦）**：`confirm_elements` 收表时会检查清单里

⇒ 整套场景**悬空**。⚠ **这是阶段一那道报红**；阶段二/三那边另有一条**共用的**
「地基漏记」报告（在越界那份文本里），**两处是两条判据**，别当成同一条。

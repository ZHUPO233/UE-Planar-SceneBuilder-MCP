## 一、目标模块（GPT 给的 8 个 + 我加的 2 个）

## 三、搬迁顺序（**如果**将来真搬）

⚠ 前提是**功能冻结**。冻结之后按"依赖从下往上"搬，每一步都能单独跑预检：

1. **`ue_adapter.py`** —— 先把 `call_official` / 连接 / 厚函数搬走（**零业务依赖**，最好验）
2. **`state.py`** —— 状态文件 + 三道横切闸（`_readback_guard` / `_session_prereq_guard` / `_change_request_guard`）
3. **`planning.py`** / **`assets.py`**（互不依赖）
4. **`verification.py`** → **`surfaces.py`** → **`build.py`**（这条有真实调用边，顺序不能反）
5. **`environment.py`** / **`exchange.py`**
6. 最后才动 **`workflow.py`**（19 个工具壳）

**为什么这个顺序**：`workflow.py` 一层是**唯一会同时"看见"所有模块**的地方 —— 它最后动，前面每一步都不需要改它；反过来先动它，会让每一步都要重新对齐。

## 四、这份设计**不**做的事（别拿它当开工令）

- **不搬任何一行** —— 今天一个字节都没动。
- **不做接口命名 / 类型签名设计** —— 那要等"谁调谁"定稿；现在写了也是猜。
- **不承诺行数会变少** —— 拆模块通常**增加**总行数（import、`__init__`、边界注释）；它买的是**可读性**，不是行数。
- **不做"顺手清理"**：拆分时**只搬不改**（GPT 原话「机械迁移」）—— 任何"顺便改个名 / 顺便修个 bug"都会让预检失去判据（改坏了分不清是搬坏的还是改坏的）。

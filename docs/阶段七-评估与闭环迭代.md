## 二、`evaluate_layout()` 是什么

**只读工具**：不碰关卡、不存盘、**不改 `plan_v1.json` 一个字**；唯一写的是我们自己的报告
`views/evaluate_v1.json`（**不进几何指纹** —— 写报告不该让上一次确认作废）。

**对的是三份东西**：

| 来源 | 文件 / 怎么拿 | 它代表什么 |
|---|---|---|
| ① 确认过的放置表 | `views/plan_v1.json`（**权威几何**，米） | 「用户点头过的那一版」 |
| ② 搭建台账 | `views/build_state_v1.json`（阶段三写） | 「上次到底搭了什么、落在哪个 Actor 上」 |
| ③ 关卡现状 | 官方读回（`get_actors_in_folder` / `get_actor_transform` / 组件 `RelativeScale3D` / `overrideMaterials`） | 「UE 里**现在**实际是什么样」 |

**比五样**（每一维的判据都**复用现有那几处**，绝不另造一套 —— 两套口径 = 两处会说不同的话）：

| # | 维度 | 判据（复用谁） | 抬头结论（`verdict`） |
|---|---|---|---|
| ① | 行在不在台账里 | `uid = element_key\|label` | `never_built` 没搭过 |
| ② | `plan` ↔ 台账（离线也能比） | `_row_changes()` —— 与增量搭建**同一个**判据 | `plan_changed` 改过 plan 没重搭 |
| ③ | 台账 ↔ 关卡 | `_live_vs_ledger()` —— 位置容差 0.5 cm（判的是「人手动挪过没有」）、白膜另读组件尺寸 | `drifted` 关卡里没了 / `edited` 现状与台账不符 / **`unchecked` 没比成**（读失败 / 白膜尺寸读不回来 —— **2026-10-04 加**，见下） |
| ④ | 分组 | 每个 `UEMCP/<类>` 读一次（**不递归**），比引用集合 | 落进 `groups`（应到 / 实到 / 缺 / 多） |
| ⑤ | 材质（`include_materials=true`，默认开） | `_surface_read_row()` + `_surface_matches()` + `config/surface_materials.json` | `material_missing` 对不上 / `material_unreadable` 读不到（**不判没贴**） |

**抬头结论的优先级**（一行可能同时命中几条，`why` 里带**全部**原因）：
`never_built` > `drifted` > `plan_changed` > `edited` > `material_missing` >
`material_unreadable` > `unchecked` > `ok`
—— 排序依据是**要动手的紧迫度**，`ok` 永远最后：它是「没命中任何一条」的兜底，
**不是「检查通过」的合格证**。

## 三、三条「如实报」的硬口径

1. **UE 连不上时不报错**：它**只出 `plan ↔ 台账` 那半**，并在 `warnings` 里点名
   「**关卡那一维这次没查**（变换 / 白膜厚薄 / 分组 / 材质 / 人工痕迹一个都没查）」。
   → **不许把「这次没报」当成「没问题」**。
2. **「没比成」也不许当成「没问题」**（2026-10-04 加固）：`_live_vs_ledger()` 现在会把
   **引用为空 / 引用不在关卡里 / 读变换失败 / 白膜尺寸读不回来**这四类行**逐条带原因**返回；
   `evaluate_layout` 给它们判 **`unchecked`** 并把原因写进 `why`（以前它们会一路掉到 `ok` ——
   而 `ok` 是「没命中任何一条」的**兜底**，不是合格证）。`execute_build` 那边同样报进
   `warnings` 与 `diff["关卡现状没比成的行（≠没问题）"]`。
   ⚠ **只报不拦**：读不到多是偶发（官方抖一下 / 引用被重建），拦下去会让整次搭建白跑。
3. **台账记的不是这张图时不硬比**：`台账关卡 ≠ 当前关卡` → 关卡那一维**整段跳过**并说明
   （台账里的 Actor 引用在别的图上没有意义）；要在这张图上对账，先
   `execute_build(mode="incremental", adopt=true)` 把现状认领成新基线。
4. 同理，**没有台账**时每一行都判 `unchecked`（**「没比成」不等于「没问题」**）。

## 四、闭环：就是现有那条五步链（**不新造工具**）

用户说「第 3 栋往左挪 5 m」之后，走的是：

```
request_plan_change(items=["第 3 栋往左挪 5 m"], by="用户")   ← 先留痕「改什么 / 谁要的」
        ↓
generate_plan(patch=[{"op":"set","label":"住宅 #3（house1）","set":{"pos":[…]}}])   ← 只改那几行
        ↓
（你重画图：图内写新几何指纹 + 本轮该覆盖的那几行 label）
        ↓
confirm_plan(confirmed_by="用户", user_quote="行")            ← 用户看图点头；没原话 = 拒收
        ↓
execute_build(dry_run=true) → execute_build()                     ← 默认增量，只重摆差异行
```

⚠ **`request_plan_change` 是「改动窗口」的钥匙**（代码硬拦）：一份规划**被确认过之后**，
再改内容必须先调它，否则 `generate_plan` 直接拒收（一个字节都不写）。窗口开到下一次
`confirm_plan()`。**自查修正也要记**（`by="agent 自查"`）—— 要的不是「等用户开口」，
是留下「改什么 / 谁要的」这层对应关系。

⚠ **为什么不把这条链包成一个「一键闭环」工具**（我给用户的反驳意见，他采纳了）：
那等于把「**用户看图点头**」那道闸从中间绕过去 —— 客户已经当场质问过一次
（「你摆你牛魔呢，图都不先让我确认就摆」）。`evaluate_layout()` 只负责**把差异说清**，
并在 `next_step` 里指出该走上面哪一步。

⚠ **另有一条**「**四 · 微调**」（2026-10-04 用户拍板新增的阶段，**不新造工具**）：
**整体搭建完成之后的小改**走的是这条链的**收窄版** —— `request_plan_change`（记用户原话）→
`generate_plan(patch=…)`（plan 与搭建台账两边一起改）→ `execute_build(only_labels=[…])`
（**只动点名的那几行**）。⚠ 它**不出图、不要二次确认**（**没有**上面那两步「重画图 → 看图点头」），
验收 = **用户在 UE 里自己看**、agent 报数字；`get_plan().acceptance.state` 那时显示
**`tuned`（微调版 / 这一次没有图）** —— 那是**预期的**（`planning.mark_tuned()` 写
`confirmation.mode = "tuned"`，`acceptance_state()` **最先**认它）。
要回到「有图那种正常验收」：**重画两张图 → `confirm_plan()`**。

## 五、出图（本阶段的另一半）

`capture_preview()` 是 2026-09-29 在阶段六期间做出来的，**已划归阶段七**：
按**世界坐标**摆机位出图（`captureTransform`），**不动用户的视口相机**（实测：出图前后
`GetCameraTransform` 一字不变 → 可以连拍）；两档：干净图 / 带标注图（世界网格 + Actor 标签）。

⚠ 三条实测到的坑（别当 bug 报）：
① 官方**画不出中文** —— 图上标签渲染成乱码（JSON 里回报的字符串是对的，UE 侧字体没有中文字形），
**十字准星与引线仍有效**；
② `bShowUI=false` **挡不住**编辑器角落的坐标轴指示与 `PlayerStart` 图标；
③ 图**不回传给模型**（实测 0.87~1.07 MB/张）—— PNG 落 `views/preview/`，要看图**读文件**。

# 阶段三 · 资产布局生成（2026-09-26 已实现）

**解决什么**：活动那份 plan（纪元 1 = `views/plan_v1.json`，**纪元 2 = `views/plan_v2.json`**，走 `planning.active_plan_path()`）是米、只有平面 `pos` 与 `z_m`，UE 吃不下 —— 阶段三把它翻成 UE 能照做的搭建指令，动手前把该拦的拦掉。

**第一步 `check_build_target()`（不碰关卡）**：读当前关卡、列出项目里的关卡资产、看 `UEMCP/` 下有没有上次摆的东西，输出要问用户的一句话 + 三个选项（开新图 / 指定既有图 / 就用当前图）。⚠ **官方没有"新建关卡"工具**（实测只有 `load_level`），选开新图得**用户自己**在 UE 里建好。

**它现在是两步，而且第二步是硬闸（2026-09-26 加；✅ **2026-10-07 已实测** —— 答复台账 `views/build_target_v1.json` 里 `decision=current` / `level=/Game/demo/Landscape/MCP95` / `user_quote=「关卡定我现在开着的MCP95」`）**：① **先问**（`decision` 留空，只读地问一遍）→ 把 `question` / `options` 交给用户、**停下等他打字**；② 拿到他的话**再调一次**，带 `decision`（`current` / `existing` + `target_level` / `new`）+ `user_quote`（他的**原话**，缺了当场拒收）—— 把答复记进 `views/build_target_v1.json`。之后 `execute_build()` 会拿这份答复**核对当前关卡**：选 `new` 而他还没换图 / 指定了别的图 / 中途换了图 —— **一律拒收，一个 Actor 都不动**（`adopt=true` 不拦：它不碰关卡，只把现状读成台账）。⚠ 为什么要它：这条以前只写在工具描述和本文档里（客户反馈：Agent 会跳过它直接搭）。**"拿到答复前一个 Actor 都不许放"现在由代码拦。**

**第二步**：`execute_build()` 按当前 plan 重算 → **整批校验**（闸门 / 指纹 / 验收状态 / 用户原话 / 逐个 `exists()` / 行数相符 / 白膜自洽，**一条不过就一个 Actor 都不落**）→ **①.5 顺手落一份留痕件**（内部件 `_orders_snapshot()` 把这一版 plan 的指令表重算到 `views/build_orders_v1.json`，**厘米**；⚠ **真跑也写** —— 原文那半句"`execute_build(dry_run=true)` 纯离线出这张表"**已作废**：演练整段删除后它一度成了孤儿（`def` 在、零调用点），留痕件于是**永远停在上一版**，还害 `check_build_target` 比出一个假的"数量对不上"；2026-10-12 补回成第 ①.5 步。它**只写我们自己的 JSON**、不碰关卡、算不出来**不挡搭建**，失败只留一条 warning）→ **开场动作闸** + **不许悄悄全量清场** + **人工痕迹闸**（都见下）→ 只清 `UEMCP/` 下的旧 Actor（关卡自带的方向光 / 天空 / PlayerStart **一个都不碰**）→ 按表落（资产 `add_to_scene_from_asset`；白膜 `add_to_scene_from_class` + `PrimitiveTools.add_cube`）→ 读回 `get_actor_transform` **与白膜组件的 `RelativeScale3D`（尺寸）**对账。**绝不存盘。**
⚠ 签名（**以代码为准**）：`execute_build(mode='auto', force_full=False, adopt=False, verify=True, batch=False, user_quote='', only_labels=[], confirm_stage3='')` —— **没有 `dry_run`、没有 `accept_user_edits`**（两个形参 2026-10-12 已整段删除）；`batch` 默认 **`False`**（逐行老路，见第 ② 条）。

**第三步（阶段三的结束判据）· 换纪元 —— `mode` 解析为 `full` 时由整批落地**自动触发**（2026-10-15 改；手工旁路 `execute_build(confirm_stage3=…)`（2026-10-04 加；2026-10-12 改成"并进落地那一次调用"；✅ **2026-10-08 已实测** —— `views/build_state_v2.json` 报 `epoch: 2`、`views/plan_v2.json` 已在 ⇒ 这一次切换真发生过）** —— 落完、**用户在 UE 里看过**之后，这一阶段的收尾不是"再确认一次规划"，而是**换纪元**：旧 plan / 旧台账 / 旧资产表**冻结留档**，**新 plan（`views/plan_v2.json`）+ 新台账（`views/build_state_v2.json`）+ 新资产表（`catalog/asset_list_v2.json`）**接管后面所有阶段（四~八）。
· **切换是落位的前置，不是另一次调用**（用户原话：「三阶段只触发一次，就是把第二阶段的规划落地到 UE，只进行一次批量操作然后直接冻结纪元 1 开启纪元 2…一旦落进关卡代码自动结束前三阶段且不可回到前三阶段」）：**整批落地（`mode` 解析为 `full`）⇒ 自动**：这一次调用先把纪元切了、再当场落位（2026-10-15 改）。三条判据都要过，不过就拒收（**一个 Actor 都不动**）并说清差哪条：① 现在还是**纪元 1**（`views/plan_v2.json` 不存在 —— 纪元只开一次）；② 拿**当前活动台账**核阶段三**真的落完了**（每一行都落成：`ok=false` / `verified=false` / `mismatch` 一个都没有；老台账缺 `ok` 字段时按「有 `actor` 引用」算；**台账一行都没有**也不算落完）；③ **有触发来源**：整批落地**自动触发**，或手工旁路 `confirm_stage3`（凭据按「调用方声明·工具无法核实」留痕）。⚠ 2026-10-15 起**不再要求用户原话** —— 人的授权在上游（阶段二确认的满 5 秒闸 + 整批校验 + G16）。
· 切换做四件事（顺序固定）：`planning.promote_to_epoch2()`（把 `plan_v1.json` 的 `confirmation` 标 `frozen_at` / `frozen_by=epoch2` + 归档一份进 `views/archive/` + **整表照抄**写出 `plan_v2.json`）+ 把 v1 台账**整表接力**成 `build_state_v2.json`（带 `"epoch": 2`，**不重摆、不重对账** —— 换的是"哪份文件算数"，不是现场）+ **`catalog/asset_list.json` 逐字节照抄成 `catalog/asset_list_v2.json`**（2026-10-12 用户要求「把资产表和位置表一样的方式进纪元 2」；搬没搬成**都会写进报文**，不许留下"位置表已是 v2、资产表还是 v1"那种半切换）+ **然后才清场 / 落位**。
· ⚠ **几何指纹故意逐位不变**（`confirmation` 不进指纹）⇒ 换纪元**不作废任何确认**、也不让 `views/evaluate_v1.json`（G15 / G16 那份现场报告）过期。⚠ 新 plan 的几何指纹与 v1 **逐位相同** —— **这是刻意的**。
· ⚠ 它与 `only_labels` / `mode` 非 `auto` / `force_full` / `adopt` / `user_quote` **互斥**（那些都是"要动 Actor / 认领现状 / 覆盖手改"的开关 —— 参数不许被静默吞掉）。⚠ **代码实况**：`confirm_stage3` 非空时 `mode` **只许 `auto`**（写 `full` / `incremental` 都在互斥那一道当场拒收）—— 所以**别再照 `execute_build` 形参说明里那句「`mode` 只许 `auto` 或 `full`」去讲**，那一句**已于 2026-10-15 修掉**（`tools.py` 包装层与 `main.py` 现已同口径：只许 `auto`）。
· ⚠ 切换走 `write_plan()` ⇒ 会顺手挂一条「**待回读**」：**先调一次 `get_plan()`** 再往下走。
· 此后（阶段四及以后）改行走 `request_plan_change` → `generate_plan(patch=…)` → `execute_build(only_labels=[…])`，**不画图、不重确认**；`plan_v1.json` 与 `build_state_v1.json` **冻结只读**（⚠ **2026-10-08 已按用户指令删除**、留档在 `views/archive/`；原「纪元 2 已开而活动目标退回 v1 ⇒ 拒收」那道闸的触发条件**恒不成立，已于 2026-10-07 删除** —— 现在「v2 读不动」由咽喉如实表现为**"没有规划"**，各闸自己拒收）。口径的**唯一咽喉**：`planning.active_plan_path()` / `active_plan()` / `active_epoch()` + `main.py` 的 `active_ledger_path()` + `planning.active_asset_list_path()`（**判据只有"文件在不在"**：v2 在 ⇒ 永远是它，v2 不在 ⇒ 才轮到 v1）。

**开场动作闸（2026-09-26 加；**尚未实测**）** —— 客户 Agent 自评承认漏掉的两条：「开场先调 `get_asset_list` —— 没调（开场只调了 `get_plan`）」「依赖官方前先 `official_status` —— 没调（直接 `tools/list` 就开干了）」。规则：`execute_build()` **真跑之前**，`official_status()` 与 `get_asset_list()` 都必须**在本 server 进程内调过**（缺哪个点名哪个；⚠ **`adopt=true` 是唯一豁免** —— 它只读现状、不碰关卡。原文写的"`dry_run` / `adopt` 不拦"里**那个演练已删**，现在只剩 `adopt`）。⚠ 这是**纪律闸**、不是正确性闸：它保证不了"你读懂了返回内容"，只保证"你调过"。⚠ 记录**在内存里**，服务重启就清零 —— 如实写清楚，不假装是永久记录。

**「没有台账却有旧 Actor」不许悄悄全量清场（2026-09-26 加；**尚未实测**）** —— 客户 Agent 自评「局部改不要全部重做 —— 反复违反，几乎每次都 `mode=full` 全量重摆」。`mode` 默认 `auto`，而 `auto` 在**没有可用台账**时会落到全量（= 把 `UEMCP/` 下**全部**删掉重摆）。现在这条被**在读现状之前**拦住：`UEMCP/` 下已有我们摆的 Actor、却没有可用台账（第一次搭那次没写 / 换了关卡 / 台账被删）→ 拒收，并给出两条出路：**先 `adopt=true` 认领现状**（一个 Actor 都不动，推荐），或 `mode="full", force_full=true`（⚠ 真跑若还要按 plan 覆盖人工痕迹，另配 `user_quote` —— 见下面那条两步闸；**`accept_user_edits` 这个开关 2026-10-12 已删，别再加**）。

**人工痕迹闸（2026-09-26 加；2026-09-30 两次加固；2026-10-12 随"删演练"简化）** —— 客户 Agent 使用后自评点名的那条「用户手动改的东西不该删 —— 我 full 重摆给删了」：动手前先**读一遍关卡现状**与台账逐行比（位置 / yaw / 缩放 / 白膜厚薄），**对不上的行**、以及**台账里根本没有的活 Actor**，默认 **拒收并列出来**（一个 Actor 都不动）。
⚠ **要按 plan 覆盖它们（真跑）＝ 用户本人的决定，而且现在是**两步闸**（**两步、只用一次调用就能走完**）**：
① 先按**默认参数**调一次 `execute_build()`（或 `execute_build(only_labels=[…])`）—— 它列清单 + **拒收**，并**留痕「这一批问的是哪几行」**（`views/user_edits_v1.json`，一个 Actor 都不动）；
② **把清单原样交给用户、停下等他打字**；③ 拿到**他本人的原话**，再调一次带 `user_quote="他回的整句"`（**只带 `user_quote` 就够了** —— ⚠ 原文那句"再带 `accept_user_edits=true` + `user_quote`"**已作废**：那个开关 2026-10-12 随演练一并删除）。
**对外只有两步，工具侧只核对两件事**（2026-10-04 收缩）：① **是不是这一批**（多一行少一行都重问；"还没问过"是它的特例）② **有没有他本人的原话**（空原话 = 拒收）。另有一道**地板**：距提问 ≥ 5 秒（`MIN_USER_EDITS_ANSWER_DELAY_S`，只挡"问完立刻自己答"，不承担防伪造）。⚠ **内部完整清单不再单独维护**（原「闸门总表」`docs/全流程-闸门地图.md` 已于 `v0.9.0` 删除、2026-10-05 定案**不重建** —— 判据只在**代码里的拒收原文**），本文只讲这两步。
⚠ **不许自己编一句原话**（编了就是伪造人的确认）—— 想让用户先看清"会覆盖什么"，就先用上面 ① 那次**默认参数调用**（它留痕 + 拒收 + 把清单摆出来）；⚠ **演练档（`dry_run`）2026-10-12 已整段删除**，全工程都没有了，别再提它。
⚠ **这道闸能证明的东西很少，别讲大**：文字证明不了"人真的看过"（代码验不了真话）—— 它做到的是**不能悄悄干**（空原话直接拒收）+ 台账里留着那句话可事后对质。
⚠ **2026-10-04 撤掉了当时的「应答码」**（用户原话：「把这个什么码删掉，太离谱了」）：它曾要求用户把第 1 步报文里的码（`覆盖41行-3f2a`）念回来才让真跑，补的是"拿一句**更早说过的话**顶 `user_quote`"那个洞（实测：有 agent 拿提问之前那句话当答复，隔 1 分钟就覆盖了 41 行 —— 清单打印了、但没到过人手里）。**撤掉之后那个洞重新敞着** —— 如实记着，不假装还堵着。
来历（同类事故**第三次**）：2026-09-30 外部 Agent 收到拒收后**自己**传了 `accept_user_edits=true`，把用户手拖过的水面差 30 cm 覆盖掉了（第二次）；2026-10-04 又出现"拿更早的话当答复"（第三次）。差距类别落在 `diff["人工改过（现状与台账不符）"]` 与 `warnings` 里。（那个布尔开关**2026-10-12 已删除** —— 现在**凭据只有 `user_quote` 一样**，这类事故少了一条路。）
⚠ **但"拒收"只在"扫描范围"之内成立**（2026-09-30 实测更正，别再把它读成"全表拒收/全表报警"）：**纯增量真跑只扫本次会被删会重摆的那几行 —— 范围之外的人工痕迹既不拦、也不报，是「静默保留」**（东西不丢，但没人告诉你）。
⚠ **因此「两个工具会给出看似矛盾的结论」不是 bug**：`evaluate_layout()` 扫**全表**，所以它会报"有人改过"；而同一时刻纯增量的 `execute_build()` 可能一行都不报（那一行不在改动集里）。要**搭建前统一看清"有人改过什么"**，就跑一次 `evaluate_layout()`。
⚠ **扫描范围是有取舍的**（每次执行都会在报告里写清"扫描范围"）：真跑增量**只扫这次会被删掉的那些行**（代价与"动多少"成正比 —— 89 场景改 5 行 ≈ 多花 15 次调用，而不是 +189 次）；**点名（`only_labels`）时只扫点名的那几行**（2026-10-03 加）；**扫全表**只剩**两种情况**：**全量**（本来就要清全部），以及**要按 plan 覆盖人工改动**时（得先知道哪些被改过）。⚠ 原文这里列的三种情况里有 `dry_run=true` 与 `accept_user_edits=true` —— **那两个开关都已删除**（2026-10-12），别再照旧口径讲；要"统一看清有人改过什么"走只读的 `evaluate_layout()`。⚠ 判"位置改过没有"的容差是 **0.5 cm**（比读回对账的 0.05 宽）—— 人手动挪至少几厘米，浮点回写的零头不该刷假警报。

**⚠ 2026-10-03 那条"零副作用入口"已作废（`dry_run` 于 2026-10-12 整段删除）—— 现行是"两步、只用一次调用就能走完"** —— 当年踩的洞还在（用户手拖过几行、但 **plan == 台账**时，**真跑增量一行都不扫** ⇒ 不拒收、不留痕），补法是：**没给原话的那一次默认参数调用，本身就是"提问"**（留痕 + 列清单 + 拒收，一个 Actor 都不动），清单记的是 `traces` = **这一轮真跑时会被删 / 重摆的那些行**（与真跑**同一个算法** `_manual_traces_in_play()`）。标准两步：① `execute_build()`（默认参数）→ 列清单 + 留痕 → **把清单交给用户、停下等他打字**；② 隔 **≥5 秒** → `execute_build(user_quote="他的原话")` → **只动那几行**。⚠ 第 2 步的判据**一条都没放松**。
> **历史（当时还有演练档，2026-10-04 之前；演练已于 2026-10-12 整段删除）**：那时第 1 步是 `execute_build(dry_run=true)`，它顺带留痕（本来就扫全表、列清单；写的是我们自己的 JSON，关卡一个 Actor 都不动）；第 2 步要 `accept_user_edits=true` + `user_quote`。**现在这两样都没有了。**
**点名重摆（`only_labels`，2026-10-03 加）**：`execute_build(only_labels=["那几行的 label"])` = **只把关卡里被手拖偏的那几行按 plan 摆回去**（替掉"为了挪 2 行得先全量重摆"那条烂路）。真跑**必须**配 `user_quote`（不给 ⇒ 拒收）；与 `mode="full"` / `adopt` 互斥；label 必须唯一命中 plan、台账里要有这一行；**本来就对的行跳过**并如实报；扫描范围收窄到点名那几行。

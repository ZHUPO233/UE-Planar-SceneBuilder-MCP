# 阶段三 · 资产布局生成（2026-09-26 已实现）

**解决什么**：`plan_v1.json` 是米、只有平面 `pos`、没有 Z，UE 吃不下 —— 阶段三把它翻成 UE 能照做的搭建指令，动手前把该拦的拦掉。

**第一步 `check_build_target()`（不碰关卡）**：读当前关卡、列出项目里的关卡资产、看 `UEMCP/` 下有没有上次摆的东西，输出要问用户的一句话 + 三个选项（开新图 / 指定既有图 / 就用当前图）。⚠ **官方没有"新建关卡"工具**（实测只有 `load_level`），选开新图得**用户自己**在 UE 里建好。

**它现在是两步，而且第二步是硬闸（2026-09-26 加；**尚未实测**）**：① **先问**（`decision` 留空，只读地问一遍）→ 把 `question` / `options` 交给用户、**停下等他打字**；② 拿到他的话**再调一次**，带 `decision`（`current` / `existing` + `target_level` / `new`）+ `user_quote`（他的**原话**，缺了当场拒收）—— 把答复记进 `views/build_target_v1.json`。之后 `execute_build()` 会拿这份答复**核对当前关卡**：选 `new` 而他还没换图 / 指定了别的图 / 中途换了图 —— **一律拒收，一个 Actor 都不动**（`dry_run` 与 `adopt` 不拦：它们不碰关卡）。⚠ 为什么要它：这条以前只写在工具描述和本文档里（客户反馈：Agent 会跳过它直接搭）。**"拿到答复前一个 Actor 都不许放"现在由代码拦。**

**第二步**：`generate_build_orders()` 纯离线出 `views/build_orders_v1.json`（厘米）；`execute_build(dry_run, verify, accept_user_edits, user_quote)` 才碰 UE —— 按当前 plan 重算 → **整批校验**（闸门 / 指纹 / 验收状态 / 用户原话 / 逐个 `exists()` / 行数相符 / 白膜自洽，**一条不过就一个 Actor 都不落**）→ **开场动作闸** + **不许悄悄全量清场** + **人工痕迹闸**（都见下）→ 只清 `UEMCP/` 下的旧 Actor（关卡自带的方向光 / 天空 / PlayerStart **一个都不碰**）→ 按表落（资产 `add_to_scene_from_asset`；白膜 `add_to_scene_from_class` + `PrimitiveTools.add_cube`）→ 读回 `get_actor_transform` **与白膜组件的 `RelativeScale3D`（尺寸）**对账。**绝不存盘。**

**开场动作闸（2026-09-26 加；**尚未实测**）** —— 客户 Agent 自评承认漏掉的两条：「开场先调 `get_asset_list` —— 没调（开场只调了 `get_plan`）」「依赖官方前先 `official_status` —— 没调（直接 `tools/list` 就开干了）」。规则：`execute_build()` **真跑之前**，`official_status()` 与 `get_asset_list()` 都必须**在本 server 进程内调过**（缺哪个点名哪个；`dry_run` / `adopt` 不拦 —— 一个只看、一个只读现状）。⚠ 这是**纪律闸**、不是正确性闸：它保证不了"你读懂了返回内容"，只保证"你调过"。⚠ 记录**在内存里**，服务重启就清零 —— 如实写清楚，不假装是永久记录。

**「没有台账却有旧 Actor」不许悄悄全量清场（2026-09-26 加；**尚未实测**）** —— 客户 Agent 自评「局部改不要全部重做 —— 反复违反，几乎每次都 `mode=full` 全量重摆」。`mode` 默认 `auto`，而 `auto` 在**没有可用台账**时会落到全量（= 把 `UEMCP/` 下**全部**删掉重摆）。现在这条被**在读现状之前**拦住：`UEMCP/` 下已有我们摆的 Actor、却没有可用台账（第一次搭那次没写 / 换了关卡 / 台账被删）→ 拒收，并给出两条出路：**先 `adopt=true` 认领现状**（一个 Actor 都不动，推荐），或 `mode="full", force_full=true, accept_user_edits=true`（**两个都要给**）。

**人工痕迹闸（2026-09-26 加；2026-09-30 两次加固）** —— 客户 Agent 使用后自评点名的那条「用户手动改的东西不该删 —— 我 full 重摆给删了」：动手前先**读一遍关卡现状**与台账逐行比（位置 / yaw / 缩放 / 白膜厚薄），**对不上的行**、以及**台账里根本没有的活 Actor**，默认 **拒收并列出来**（一个 Actor 都不动）。
⚠ **要按 plan 覆盖它们（真跑）＝ 用户本人的决定，而且现在是**两步闸**（2026-09-30 第二次加固）**：
① 先按**默认参数**调一次 `execute_build()` —— 它列清单 + **拒收**，并**留痕「这一批问的是哪几行」**（`views/user_edits_v1.json`）；
② **把清单原样交给用户、停下等他打字**；③ 再带 `accept_user_edits=true` + `user_quote`（他的原话）调第二次。
判据四条缺一条就拒收：**问过** / **问的那批就是现在这批**（多一行少一行都重问）/ **有他本人的原话** / **答复距提问 ≥ 15 秒**（`MIN_USER_EDITS_ANSWER_DELAY_S`）。
⚠ **不许自己编原话**。⚠ **边界（不吹）**：拦不住"存心等够时间再编一句话"（代码验不了真话），但台账里留着「问过哪几行 + 那句话原文」可事后对质。
来历（同类事故第二次）：2026-09-30 外部 Agent 收到拒收后**自己**传了 `true`，把用户手拖过的水面差 30 cm 覆盖掉了；后来"你手挪的售卖机被我复原了"也是同一类。差距类别落在 `diff["人工改过（现状与台账不符）"]` 与 `warnings` 里。
⚠ **但"拒收"只在"扫描范围"之内成立**（2026-09-30 实测更正，别再把它读成"全表拒收/全表报警"）：**纯增量真跑只扫本次会被删会重摆的那几行 —— 范围之外的人工痕迹既不拦、也不报，是「静默保留」**（东西不丢，但没人告诉你）。
⚠ **因此「两个工具会给出看似矛盾的结论」不是 bug**：`evaluate_layout()` 扫**全表**，所以它会报"有人改过"；而同一时刻纯增量的 `execute_build()` 可能一行都不报（那一行不在改动集里）。要**搭建前统一看清"有人改过什么"**，就跑一次 `evaluate_layout()`。
⚠ **扫描范围是有取舍的**（每次执行都会在报告里写清"扫描范围"）：真跑增量**只扫这次会被删掉的那些行**（代价与"动多少"成正比 —— 89 场景改 5 行 ≈ 多花 15 次调用，而不是 +189 次）；**扫全表**的三种情况是 `dry_run=true`（"看清楚"那一步，问"我手改的东西还在不在"就靠它）、`accept_user_edits=true`（要覆盖就得先知道哪些被改过）、全量（本来就要清全部）。⚠ 判"位置改过没有"的容差是 **0.5 cm**（比读回对账的 0.05 宽）—— 人手动挪至少几厘米，浮点回写的零头不该刷假警报。

**增量（2026-09-26 加，**已实测**）**：场景已搭好时不必全量重摆 —— `execute_build(mode="incremental")` 只动"与台账比变了的行"（新增 / 改动 / 删掉），其余行一个 Actor 都不碰。⚠ **`mode` 默认已是 `auto`**（2026-09-26 改：原先默认 `full`，于是没读参数说明的 agent 每轮全清重摆 89 个、白干好几轮）：有对得上的台账就走增量，没有才全量；**显式 `mode="full"` 真跑还要 `force_full=true` 才放行**（拒收时会告诉你这次其实只变了几行）。台账 = `views/build_state_v1.json`（我们自己的文件，**非 UE 存盘**），靠每行的 `uid`（`element_key`|`label`）对齐。还没有台账就先 `execute_build(mode="incremental", adopt=true)` **认领现状**（只读 label + 变换 + 白膜尺寸，不动 Actor）。台账缺失 / 换了关卡 / `UEMCP/` 下有台账解释不了的 Actor → **拒收，一个 Actor 都不动**。局部改动的循环：改 plan（`generate_plan(patch=[...])`，只发改动的那几行）→ **重画图（写新指纹 + 本轮变更集那几行；⚠ 每一版都出**两张**：顶视图（X-Y）+ 原图视角正视图（Y-Z），见 `docs/阶段二-平面放置规划.md`）→ 用户看图确认 → `generate_build_orders()` → 增量落。⚠ 从 2026-09-26 起**图与确认也是局部的**（见 `docs/阶段二-平面放置规划.md` 的变更集口径）：只改了几行，就只画那几行、只确认那几行。

**实测证据（2026-09-26，真跑；⚠ 这是开发者在自己的 demo 工程上的记录，不是你当前工程的状态）**：一个已搭好 89 个 Actor 的场景里，把 5 行白膜各加宽一倍 —— `patch` 只改 5 行 → 变更集 `changed=5 / same=84` → 局部图只画这 5 行即被认账 → `adopt` 认领 89/89（283 次只读调用）→ 增量落 **removed 5 / placed 5 / verified 5 / mismatches 0**、`UEMCP/` 仍 89 个、**31 次官方调用**（全量重摆是 383 次）。复核：被改的那几个白膜组件 `RelativeScale3D.x = 4`。
⚠ **两个真跑才暴露的坑**（已修，别再犯）：① `adopt` 若照抄**当前指令表**的白膜尺寸当基线，会把"刚改大的那几行"判成"没变"→ **静默不摆**；白膜尺寸**只能从组件的 `RelativeScale3D` 读**（`get_components` → 组件名 `cube` → `ObjectTools.get_properties`，×100 = 厘米），读不到就记 null（安全侧重摆）。② 增量差异里 `changed` 存的是 `(指令行, 台账旧行, 说明)` **三元组**，按两项解包会 `AttributeError: 'list' object has no attribute 'get'`。

**排障入口**：工具报"光秃秃一句错"（没正文）时，完整栈在Agent的 `%APPDATA%\dsh-desktop\logs\harness.log` —— 搜工具名就能看到 `main.py:行号`（Agent只显示 ToolError 的正文，别的异常一律只显示 `Error executing tool xxx`）。

**口径**：米 ×100、不翻轴；`ue_yaw = rot_deg`（实测同向，**不反号**）；官方**没有 `add_plane`** → `plane` 压成极薄 cube；材质不贴（留给阶段五）；Z 口径在代码常量 `WHITEBOX_VERTICAL` / `GROUND_Z_M` / `ASSET_PIVOT_LIFT_CM`（路面 z=0、两侧地面顶面 15 cm；原点不在底面的资产如树要抬高，树实测高 31.44 cm）。**只读 plan，不改它。**
⚠ **资产的 Z 尺寸（2026-09-30 加）**：`RelativeScale3D = [scale, scale, scale × scale_z]` —— `scale_z` 是 plan 里那个**选填的 Z 方向倍率**（默认 1.0，`1.0` 不写进数据）。**只拉高 / 压低、占地一个数都不动**（改 `scale` 是整体缩放，占地同时变）。增量差异里 Z 分量变了会**点名写成「**Z 分量变了 = 高度变了**」**（与白膜那边「第 3 维 = 厚薄 / 高度变了」同一条纪律）—— 因为那种改动**只有立面图看得出来**（见 `docs/阶段二-平面放置规划.md` 的两种图口径）。
⚠ 指令表每行还多带 **`z_base_cm` / `z_top_cm` / `bbox_cm`**（2026-09-30 加）：**底 / 顶绝对标高与占位包围盒**，与 `get_plan().drawing` **同一处口径**（`_compose_build_rows()` 里算，不另推一遍）。

**搭建顺序：五层**（2026-09-27 用户指令：「先搭建世界地基再到地皮，再到建筑层再到设施层，最后才是植被层」）—— 常量 `BUILD_LAYERS`：

| 层 | element_key | 为什么在这层 |
|---|---|---|
| ① 世界地基 | `ground` | 整块世界垫在最下面。**顶面 = 两侧地面 15 cm**（`GROUND_Z_M`）→ 房子底面 15 cm 正好坐上去、草坪顶面 15 cm 与它齐平、车行道（顶面 0 / 厚 15 → 占 −15～0）**正好嵌进去**（"车行道比两侧地面低 15 cm"本就是 `GROUND_Z_M` 的定义）。厚度由 plan 的 `height_m` 给（建议 20 cm，**口径值不是实测**）。⚠ plan 里没有这一行时这层就是空的 —— 不会凭空生底板 |
| ② 地皮 | `grass` | 地面覆盖层 |
| ③ 建筑层 | `house` | 主体 |
| ④ 设施层 | `road`、`sidewalk`、`path` | **道路 / 人行道归设施**（用户 2026-09-27 在选项里定的，不归地皮） |
| ⑤ 植被层 | `tree`、`shrub` | 配景 |

⚠ 同层内保持 **plan 原序**（资产行在前、白膜行在后）；`index` 是**排完五层再重新编号**的。⚠ 不在五层表里的 `element_key` 落到最后「（未分层）」并在报文点名（免得新元素静默跑到最前面）。⚠ Actor 名**不跟 index 走**（`_safe_actor_name` 只用 label），所以重排**不会让已有台账的 Actor 名失配**（增量仍按 label 认领）。⚠ 这一步**只改落进 UE 的先后**，plan 的两张表一个字不动（几何指纹、确认图、`uid` 对账都不受影响）。

⚠ **「读回对不上」这条：只有报告、没有退路**（2026-09-30 用户点名问过；这是本阶段**已知的、故意留着的缺口**）：`_verify_rows()` 逐行读回比对 —— 位置容差 **0.05 cm**、yaw 按**角度差**比、缩放 **1e-4**；白膜在 `verify="full"` 档再读组件 `RelativeScale3D` 比尺寸。对不上的行进 `mismatches` **逐条点名**，**台账照写**（记的是**读回来的真实值**，不是指令值 —— 硬规则 6 那条"预估值不许冒充实测值"）—— **不回滚、不重试、不中止后续行**。

  - **为什么没有"回滚"**：这一阶段落一行 = `remove_from_scene` + 重新 `add_*`，**旧 Actor 已经删了、恢复不了**；UE 侧也没有事务。**能做的最多是把对不上的那一行再删掉**（=回到"没搭"，而不是"搭对"）—— 那是个**设计选择**（也可能删掉一个其实没问题、只是读数抖了一下的东西），**要用户拍板**，**没做**。

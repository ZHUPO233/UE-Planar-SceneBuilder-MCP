## 官方材质工具面 vs 我们的编排（2026-10-07 对着 `describe_toolset` 逐条核的）

**顺带抓到的两条（同一批实测）**

- **ops 档的读回核对是坏的**：`connect_output` 明明成功了（官方 `get_property_input(MP_BaseColor)`
  返回的 `expression.refPath` 就是刚连的那个节点），ops 却报「`MP_BaseColor` **读回是空的**」。
  > ✅ **2026-10-07 修**：`main.py::_ref_path()` 现在会**解开那两层已知包装**
  > （`{"returnValue": {"expression": {"refPath": …}}}`）—— 原来只认顶层 `refPath`，所以明明连上了也报空。
- **ops 只能寻址"本批 `as` 过的"节点**：拿 `refPath` 或节点名去 `delete_node` / `set_node` /
  `connect_output` 一律拒（`from` 的校验文案虽写「或已在图里的」，**实际不支持**）；
  `delete_node` 更把 `None` 传给官方（`Parameter error: None is not valid value for property
  'expression'.`）⇒ **写坏的节点收拾不掉，只能往上叠新的**。
  > ✅ **2026-10-07 修**（三条一起）：① **直接给 `refPath` 也认**（`_looks_like_ref()`：以 `/` 开头且含 `.`；
  > 这种写法**没法在图里先核**，所以**原样交给官方由它判**，不假装核过）；

  > （报"找不到引用"，而不是让官方丢一句看不出所以然的 `None is not valid…`）。

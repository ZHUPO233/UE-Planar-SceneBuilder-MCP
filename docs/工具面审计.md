# 工具面审计（Tool Surface Audit）—— 2026-09-30

> **这份是什么**：GPT「第三优先」要的那张表。**只出表，不改代码**（它原话：「不改代码，只生成一张表」）。
> **判断标准**（照 GPT 原文，我同意这条）：**不是"这个 Tool 能不能合并"，而是"这个 Tool 是否代表 Agent 的一个有意义决策点？"**
> ⚠ **一步做完不等于现在就该动手**：真要合并 / 内部化，按 GPT 第五优先的路子 —— **等所有功能冻结之后、按模块边界一起机械迁移**。这份表是那个决策的**依据**，不是它的**执行令**。

## 二、我的结论（与 GPT 的分歧也写出来）

1. **真正"只有编排价值、不承载决策"的只有 2 个**：`generate_build_orders`、`rename_assets`。
   - `generate_build_orders` 是最干净的一个 —— `execute_build` 会重算，它纯粹是**给人看的预览 + 留痕**。
   - `rename_assets` 我**同意可内部化，但理由与 GPT 不同**：GPT 标它"Agent 不主动决策"；我认为它是**危险动作**（改用户工程里的包路径）—— 危险动作**更该有个显式的名字让人看见**，而不是藏进别的工具的参数里。**所以我的判断是：暂不内部化**。
2. **绝不能内部化的 3 个**：`get_plan`（回读闸的钥匙）、`confirm_plan`（证据链）、`check_build_target`（人的选择）—— 它们本身就是闸。
3. **`export_layout` / `check_exchange` 的存疑**：它们服务的是"Blender ↔ UE 互搬"这个**目标**，而那个目标今天**没有被真用过**（`views/exchange/` 里有文件，但没人消费）。**建议：等真的搬过一次再决定** —— 在那之前合并它们只会让目标更难达成。
4. **`apply_surfaces` 是这轮之后最该重新审视的一个**：`execute_build` 现在会自动补材质，手动那条路的价值收窄成"只贴不落"。**这条要等下一次真改材质时才看得出来**。

## 三、这张表**不**回答什么（别拿它当结论用）

- **不回答"该不该减"** —— 那是你的决定；这张表只把"它是不是决策点"摆出来。
- **不回答"能不能合并"** —— 合并是**机械迁移**（第五优先），前提是**功能冻结**；现在冻结了吗？
  - 反证很具体：`[完工-19]` / `[完工-20]` / `[完工-21]` **今天都还在改 `main.py`**（9109 → 9194 行）→ **功能没冻结，所以现在不动**。
- **没统计真实调用频次** —— 那要一份调用日志；本项目**没记**（工具只报 `official_calls` 计数，不落盘）。要按"使用频率"判断（`export_layout` / `check_exchange` / `apply_surfaces`），**得先有这个数据**，否则就是凭印象 —— **不做**。

## 四、五层分层（2026-09-30 · **GPT 给的模板，分法由我定**）

> GPT 给了 5 层的**模板**（Agent / Human Approval / Execution / Environment / Internal Pipeline），并明说「怎么分还是你分」。
> ⚠ **我没照抄它那张表** —— 它把 `get_plan` / `check_build_target` / `get_asset_list` 划进"内部隐藏"，那三个是**闸的钥匙**（见下 L4），藏起来等于让 Agent 猜。**分法与三处分歧都写在下面。**
> ⚠ **分层只改"谁先看 / 谁该调"，不删任何工具、不改任何代码**（今天功能没冻结，理由见上一节）。

### L1 · 人的决策点（Human Approval）—— 5 个

**判据**：这个工具存在的**唯一**理由，就是"**停下来等人拍板**"。少了它，前面所有自动化的成果都可以被人一句话推翻。

| Tool | 为什么在这层 |
|---|---|
| `confirm_elements` | 人看参考图确认元素清单 —— 清单被污染，后面全歪（"塞猜测 = 污染他的确认"） |
| `confirm_assets` | 人确认"用哪些资产"；闸：逐条 `exists()`，一条不过一个字节都不写 |
| **`confirm_plan`** | **人看图点头**。证据链闸（必须给用户原话 + 图出炉 ≥15 s）—— **整条链最不能绕的一道** |
| **`check_build_target`** | 「**搭哪张图**」是**人的选择**（新建 / 指定 / 当前）；`_build_target_guard` 是**代码闸**：没答复就不放行 |
| `request_plan_change` | 人提"这里要改" —— 改动窗口闸的钥匙；客户 Agent 自评点名过「一次都没调过」 |

### L2 · Agent 的判断点（Agent Cognition）—— 4 个

**判据**：承载 **Agent 自己的判断**（检索 / 推理 / 自查 / 取证），**但决定权最终在人**。

| Tool | 为什么在这层 |
|---|---|
| `plan_assets` | 找资产、给候选 —— 检索是 Agent 的活，**挑哪个是人挑**（硬规则：不猜、不拿名字对不上的顶替） |
| `generate_plan` | Agent 的**空间推理输出**（坐标由 Agent 规划、代码不规划） |
| `evaluate_layout` | Agent 的**自查**：plan ↔ 台账 ↔ 关卡三方对账，是闭环的起点（只报数、不判合格） |
| `capture_preview` | **生产"能看的证据"** —— 人和 Agent 都靠它判断；⚠ 它属**阶段七**（2026-09-29 从阶段六收回），**不是"Environment"** |

### L3 · 落到实处的执行（Execution）—— 4 个

**判据**：**真的去改东西**（关卡内存 / 用户工程资产）。

| Tool | 为什么在这层 |
|---|---|
| `execute_build` | 落关卡（最终动作）。它**只读 plan + 逐条 `exists()`**，不找资产、不规划、不决策 |
| `apply_surfaces` | 改**关卡组件**的材质覆盖（`[完工-19]` 之后 `execute_build` 会自动补，手动那条路只服务"只贴不落"） |
| `setup_environment` | 改关卡的环境 Actor（太阳 / 天空 / 大气 / 天光 / 雾 / 云 / 后处理） |
| **`rename_assets`** | **唯一动"用户工程资产"的一件**（`AssetTools.move` → 改包路径）。⚠ **危险动作更该有显式名字**，所以留在明面、且保持"**默认只预览**" |

### L4 · 读状态（State Read）—— 3 个

**判据**：**只读**，但它读的东西**是闸的判据** —— 所以"只读"不等于"可以藏"。

| Tool | 为什么在这层（也是**为什么不能藏**） |
|---|---|
| **`get_plan`** | 它是**回读闸的钥匙**：不调它，`generate_plan` / `execute_build` **一律拒收**。藏它 = 让 Agent 猜"我该不该回读" |
| **`get_asset_list`** | 它是**开场动作闸**的一环（没调过就拒收）+ 报「**清单过没过期**」。藏它 = Agent 看不见过期 |
| `official_status` | 它也是**开场动作闸**的一环 + 唯一能当"链路诊断"的口子 |

### L5 · 编排内部件（Internal Pipeline）—— 3 个

**判据**：**不承载任何决策**，只是编排里的一步（翻译 / 导出 / 对账）。

| Tool | 为什么在这层 |
|---|---|
| `generate_build_orders` | **纯翻译件**（plan 米 → 指令表 厘米），而 `execute_build` **自己会重算**（实测：指令表指纹过期照样落）。它剩下的价值是**离线预览** |
| `export_layout` | 导出与 DCC 无关的场景描述（服务"Blender ↔ UE 互搬"这个目标） |
| `check_exchange` | 与外部文件对账（**只读**，出报告） |

### 三条分层纪律（比分层本身重要）

1. **MCP 里没有"半隐藏"**：`tools/list` **就是全部**。所以 L5 **不是"对 Agent 藏起来"**，而是「**照常注册 + 在描述第一行明说它是内部件**」。
   - 真要"藏"，只有两条路：**(i) 真不注册**（那工具就没人能调 —— L4 那三把钥匙绝不能这么办）；**(ii) 注册但说清**（推荐）。
2. **闸的钥匙必须在明面上**（L4 的三个是钥匙，不是流水线）—— 这是我与 GPT 那版的**最大分歧**。
3. **19 个工具一个都不删**：分层是**认知工具**（让人和 Agent 一眼看出"哪些是决策点"），不是裁剪令。

| `get_plan` | Internal（隐藏） | **L4 读状态** | **回读闸的钥匙**，藏了 Agent 只能猜 |

# 阶段四 · 微调

> **定位**：整体搭建完成之后的「**小改**」。**不新造工具**，用既有那三件。
> ⚠ **权威口径在 `AGENTS.md`「阶段四的口径」+「纪元（epoch）」两节** —— 本文件只是施工索引，
> **冲突以 `AGENTS.md` 为准**，不发明任何新口径。

## 三步不能省

1. **先记用户原话** —— `request_plan_change(items=[…], by="用户")`（自查修正用 `by="agent 自查"`）。
   它同时是「改动窗口」的钥匙：已确认过的规划要再改内容，不先调它 `generate_plan` 直接拒收。
2. **只改点名的那几行** —— `generate_plan(patch=[…])`；改完看 `get_plan().acceptance.change_set`
   的 `added / changed / removed` 与预期是否一致。
3. **只重摆那几行** —— `execute_build(only_labels=[…])`。

## 与阶段二唯一的分水岭

**不出图、也不要二次确认**（没有图、不走 `confirm_plan`）；验收 = **用户在 UE 里自己看**，
agent **报数字**（例：`Y −33.0 → −32.0`）。
`get_plan().acceptance.state` 显示 **`tuned`**（微调版 / 这一次没有图）—— 预期、如实，不是错误。
要回到「有图那种正常验收」：**重画两张图 → `confirm_plan()`**。

## 前提与硬闸

- **前提 = 纪元 2**：阶段三搭完、用户在 UE 里看过之后 `execute_build(confirm_stage3="用户原话")` 换纪元
  （`plan_v2.json` 接管、台账接力成 `build_state_v2.json`，**几何指纹逐位不变**）；换完先调一次 `get_plan()`。
- 微调版真跑：`only_labels` **不许为空**；`mode="full"` **直接拒收**；与 `adopt=true` 互斥。
- label 必须与活动 plan 一字不差、**唯一命中**，且台账里要有这一行。
- 点名真跑默认要 `accept_user_edits=true` + `user_quote`（它本质是"按 plan 覆盖手改"）；
  **唯一豁免 = 微调版**（凭据就是 `confirmation.user_quote` + `rows`）。
- **人工痕迹两步闸与 G15 / G16 照旧**：关卡里被手拖偏的行默认拒收；改数据前 / 落关卡前要有
  **当版**的 `evaluate_layout()` 报告。

## 凭据（事后对质）

`plan_v2.json` 的 `confirmation.user_quote` + `confirmation.rows`；验收台账的
`tuned_history` / `tuned_count` / `tuned_rows_total`（**只报数、不设闸** —— 要不要回一次全图由用户按需定）。

> ⚠ 下面这段**保留为当时的现象记录**（含两条拒收原文）—— 它是"两条闸互锁"的**证据**，别删。

**现象**：纪元 2（微调版 plan）里，只要一次改动**动了 `element_key` 或行名，或新增/删除行**，
落关卡**两条路都被拒**：

| 走哪条路 | 实测拒收原文 |
|---|---|
| `execute_build(only_labels=[…])` | 「这些行**在台账里没有**（= 这一行还没搭过 / 台账被重建过）—— 点名重摆只能处理**已经搭好的行**」 |
| `execute_build()`（不点名） | 「**这是微调版 plan，真跑必须点名**（`only_labels` 为空）」 |

**根因**：`only_labels` 的判据是「**台账里已有这一行**」——
改 `element_key` 会换 `uid` ⇒ 台账里那条对不上；新增行本来就不在台账里。
而「微调版真跑必须点名」那条闸又不许不点名。两条闸一夹，
⇒ **微调版实际只能改「纯几何字段」**：`pos` / `footprint_m` / `scale` / `scale_z` / `rot_deg` / `height_m`。

**实测例子**（2026-10-07 樱花街 · 第 6 版 · 指纹 `2ed036ff0a…`）：
① `自行车道（右/左）` 的 `element_key` 从 `sidewalk` 改成 `road`；② 新增 2 行 `绿化带台座（右/左）`。
两条路的拒收原文如上；`evaluate_layout()` 的旁证：`UEMCP/sidewalk` **应到 2 / 实到 4（多 2 = 那两个 uid 换掉的旧 Actor）**、
另有 **4 行 `never_built`**。

**当前出路（实测可行）**：重画两张图 → `confirm_plan()` 回「正常验收」→ **默认增量**
（它能同时删旧行 + 摆新行，正是点名那条路做不到的）。

**可选修法（未做 · 等授权）**：
- 让 `only_labels` 也接受「**plan 里有、台账里没有**」的行（新增行 / 换 uid 的行）；或
- 允许微调版在「删除 + 新增」这类**结构性**改动下退回默认增量（并如实报出会动哪几行）。

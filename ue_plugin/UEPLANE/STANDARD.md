# UEPLANE · 场景规范（STANDARD）

> 这份文件是**硬约束**，不是建议。2026-10-17 用户定案：「以后搭场景就按这种规范，写进插件里，
> 别以后新对话又是搭几个方块进去等等一堆诟病。」
>
> ⚠ **机器读的不是这份 MD**（2026-10-17 用户指出：装插件时 MD 不一定随包，也没有任何东西会自动读它）。
>   真正被每个会话读到的是**两条 Python 通道**：
>   ① `ueplane/tools.py` 里 `UeplaneTools` 的**类 docstring** = toolset 说明（`list_toolsets` /
>      `describe_toolset` 直接打印，末尾「场景规范」一节就是本文件的可执行摘要）；
>   ② `get_plan()` 的 `warnings` 里那条 📐 指路（协议要求每个会话开场先调 `get_plan()`）。
>   本文件是**人读的正文**；改规范时三处要一起改（`tools.py` 摘要 / `main.py` 的 📐 行 / 本文件）。
>
> 它约束三件事：**① 数据（plan 怎么长）② 预览页（阶段二那张 three.js 页长什么样）③ 搭建与报数**。
> 代码落点：`planning/figure3d.py`（数据层）+ `planning/web/preview3d.html`（模板产出）
> + `Tools/preview3d.shell.html`（模板源）+ `Tools/build_preview3d_template.ps1`（内联生成）。

## §1 数据规范（plan 是唯一权威）

1. **一物一行**：`assets[]` / `whiteboxes[]` 每个物体一行，**没有 `count` 字段**。20 株树 = 20 行。
2. **不做"整段代表制"**：不许用一块大板代表"整条街的铺装 + 两侧绿化 + 路面"。
   长条物（铺装、绿篱、大墙）可以是一行，但它只代表**那一层**，别把别的东西并进去。
3. **`z_m` = 该行底面绝对标高**（米），不是中心、不是原点。
4. **高度口径**：资产行 `h = 资产实测包围盒 Z(cm)/100 × scale × scale_z`；白膜行 `h = height_m`。
   查不到包围盒 ⇒ `h = 0`，页面**画成薄片**并在详情里写明"资产清单里查不到" —— **不许猜尺寸**。
5. **实测 / 预估必须分开写**：`size_source` / `note` 里写清"实测包围盒"还是"参考图目测，待核实"。
   预估值**不许伪装成实测值**。
6. **look 不准的资产先当白膜**：`is_placeholder=true` + `placeholder_shape` + 预估 `size_cm`，
   并在 `label` 里能区分（同类多行必须 label 唯一）。
7. **建筑必须逐栋成行、按参考图详细分布**（2026-10-17 用户加）：一排建筑 = **一行一栋**，
   每栋自带 `pos` / `footprint_m` / `height_m` / 朝向。
   **禁止**用一条「××建筑带」/「××大墙 120 m」代表一排建筑、一排店面或整条街的立面 ——
   那等于把参考图里的分布压成一个数字，页面与关卡都看不出"哪栋在哪"。
   分布必须能**对着参考图逐栋对位**：间距、退线、高低错落、朝向都要数得出来；
   图上数不清栋数的，按可见轮廓估个数（例：可见 6～8 段）并在 `note` 写「预估待核实」，**不许省略成一栋**。
   ⚠ 真正**连续的一件**（一道长墙、一条绿篱、一条铺装）可以是一行；**多栋**建筑不行。

## §2 预览规范（阶段二那张 three.js 页）

这张页是**用户判图的地方**，它的质量等于整个阶段的验收质量。以下每条都是踩过坑之后定的。

1. **three.js 必须内联进模板**（`<script>` 里直接放库，**不许** `<script src="three.min.js">`）。
   原因（2026-10-17 实测）：DSH 文档预览窗是 `sandbox="allow-scripts"` 的 blob: iframe，
   继承宿主 CSP `script-src 'unsafe-inline'`（不含 `blob:` / `self`）⇒ 外挂脚本被**静默拦掉**，
   页面只剩 CSS、黑屏、且**一个字都不报**。内联后 r155 正常。
2. **默认取景 = 居中**：相机目标点摆在**世界中心**，距离按包围球半径算（`fitDist()`），
   让整个世界（如 120×40 m）完整进画面且居中。**不许**一上来把相机丢到世界外面斜着看。
3. **世界中心必须画出来**：原点三色轴（X 红 / Y 绿 / Z 蓝，长 ~7 m）+ 世界边界方框 + 十字 +
   一个「世界中心 (0,0)」浮标。用户问的最多的就是"中心在哪"。
4. **每个元素都必须能被查看**（三条路都要有）：
   - 右侧**元素清单**按 `element_key` 分组、带颜色块、**点一行 = 选中 + 镜头飞过去**；
   - 三维里**单击拾取**（射线，拖动 < 4 px 才算单击），选中整体高亮成黄色、标签变黄；
   - 底部**详情面板**显示该行全部字段：平面位置 / 占地 / 底面标高 / 高 / 朝向 / scale /
     资产路径 / note / 尺寸来源。
5. **不许把树画成实心方块**。树类（`TREE_KEYS`，目前 `sakura_tree`）= 树干圆柱 + **半透明树冠椭球**
   （冠幅直接用 `footprint`）。理由：8 m 冠幅 + 12 m 株距的实心盒子 = 两堵粉墙，街道全看不见。
   新树类资产要注册进 `TREE_KEYS`，这是唯一一处。
6. **任何示意（如"原图视角"箭头）放场景外面**：世界边界外 ≥5 m，带引线指回边界；
   **不许**摆在场景里挡元素。原图视角 = 站在街道近端（`x ≈ -hx+2`、`y = 0`、眼高 1.75 m）
   **沿 +X** 看纵深。
7. **交互要顺手**：左键拖拽旋转 / 右键（或 Shift+左键）拖拽平移 / 滚轮缩放，**全部带阻尼**；
   `1` 居中 · `2` 原图视角 · `3` 顶视图 · `4` 沿街侧视 · `F` 聚焦所选 · `Esc` 取消。
8. **坐标口径只在一处换系**：plan 是左手系 Z-up → three 右手系，入口统一
   `toThree(x,y,z) = (x,-y,z)`（取反 Y）；相机用标准 `lookAt` + `up=(0,0,1)`。
   于是 UE 的 +Y 落在屏幕右侧 —— 与 plan 自己的 `right_normal(d)=(-dy,dx)` 判据一致。
   **别在第二处再取反一次**（两次 = 镜像又回来了）。
9. **共面层要错开**：地基 / 铺装 / 种植带 / 落花这类 `z` 差不多的层，按行序加 1.5 mm 递增偏移
   （`polygonOffset` 兜底），否则画面闪烁。
10. **失败必须写在画面上**：整段初始化包 `try/catch` + `window.onerror`，错误连栈打到左上角红框。
    **黑屏哑巴是本页历史上最贵的坑**（烧掉了五轮排查）。
11. **不许拿"手绘印象图"顶替这张页**。页由 `figure3d.py` 在 plan 落盘那一刻生成；
    自检（指纹 + 每行 label）不过就**不写文件**并把原因报回去。

## §3 搭建规范（阶段三往后）

1. **真网格优先**：清单里存在的资产就用它；找不到才登记白膜（见 §1.6）。不许"全都先用方块凑"。
2. **满覆盖率**：plan 里每一行都必须有对应 Actor，一个都不许静默消失。
3. **分组与命名**：落进关卡的对象归到 `UEMCP/<类>` 分组下（台账靠它做增量）。
4. **改东西只走一条路**：`request_plan_change`（记用户原话）→ `generate_plan(patch=…)` →
   `execute_build(only_labels=[…])`。**不许**用脚本或手改文件改 `plan` / `catalog` / `views` 里的 JSON。
5. **不存盘**：除阶段六环境搭建（`save=true`）之外，任何阶段都不许存盘关卡 / 资产。
6. **禁止快速搭建**（2026-10-17 用户加）：不许「先搭个大概、回头再补」；不许跳过任何闸门
   （元素清单 / 资产清单 / 规划确认 / 当版现场报告 / 回读）；不许用一块大地块凑覆盖率；
   不许只落资产行或只落白膜行；不许留临时占位 Actor 不清理。
   一次 `execute_build` 必须把 plan 的**每一行**按确认过的 `pos` / `footprint_m` / `height_m` / 朝向落进关卡，
   落完立刻 `evaluate_layout()` 做三方对账，有差异就报出来（见 §4）。
7. **严格还原参考图**（2026-10-17 用户加）：**参考图是唯一判据**。
   图上看得见的元素**一个都不能少**；尺寸 / 间距 / 朝向 / 层次（步道多宽、树离路缘多远、墙多高、
   建筑退线多少、哪一侧更密）都要按图还原，**不许"差不多就行"、不许用参数糊弄"错落"**；
   看不清的标「待核实」并给备用方案 —— **不许省略，也不许凭空加**。
   交付前逐项对照参考图过一遍：**顶视看平面、原图视角看纵深、沿街侧视看高度**，差异**报数字**。

## §4 报数规范

任何一次改动 / 搭建 / 环境配置完成后，**必须把数字报给用户**：
改了几行、哪几行、前后值（例：`Y −12.5 → −17.5`）、搭了多少个 Actor、每类几个、
坐标范围、还有几行没落地。**"改好了"不算报告。**

## §5 失败的报法

1. 工具说"没查到 / 连不上 / 没核成"⇒ **不许当成没问题**，把原话带出来。
2. 生成物（页面 / 图 / 台账）失败 ⇒ 把 `errors` 原样贴出来，并说清"哪些已经生效、哪些没有"。
3. 自己发现的错也要主动说（例：`agent 自查` 记进 `request_plan_change` 的 `by`）。

## §6 改这张页要动哪几个文件

| 想改什么 | 改哪里 | 之后做什么 |
|---|---|---|
| 页面外观 / 交互 / 新元素类型 | `Tools/preview3d.shell.html`（**壳**） | 跑 `Tools/build_preview3d_template.ps1` 重生成模板 → 重出页 |
| 页面拿到的数据字段 | `planning/figure3d.py::build_rows()` | 重出页 |
| three.js 版本 | 换 `planning/web/three.min.js` | 重跑生成脚本（会重新内联） |
| **本规范本身** | `ueplane/tools.py`（类 docstring 摘要）+ `ueplane/main.py`（get_plan 的 📐 行）+ 本文件 | 重启编辑器 / 重载插件，新会话即生效 |

⚠ `planning/web/preview3d.html` 是**产出物**（约 656 KB，three 已内联）——**不要手改**；
改完壳不重生成，改动不会生效。
⚠ 模板里数据槽位（`figure3d.SLOT`）与 three 占位**各只许出现一次**：注释里再写一遍，
注入时会被替换成一份 JSON，页子变两倍大、注释还会被撕开。
⚠ `three.min.js` 里不许含 `</script` 或 `<!--`（生成脚本会拦）。
